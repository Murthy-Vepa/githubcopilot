    Lab

    GitHub Copilot SDK

    Build changelog-gen, a .NET command-line tool that uses Copilot's agent runtime to analyze Git history, call your code, stream results, and answer follow-up questions.

    ~60 minutesBeginner to intermediate.NET 10Official SDK repository ↗
    API noteThis lab follows the current .NET SDK API: GitHub.Copilot.SDK, GitHub.Copilot, StartAsync, CreateSessionAsync, SendAsync, typed session events, and CopilotTool.DefineTool. SDK APIs can evolve; use the official README when your installed package differs.

    Objective

    The GitHub Copilot SDK exposes the agentic engine behind Copilot CLI as a library you can embed in an application. In this lab you will build a practical .NET CLI tool that combines sessions, streaming, custom tools, and multi-turn conversations.

    By the end, you will understand:

    • How the Copilot SDK relates to Copilot CLI and the wider Copilot platform
    • How to create and manage Copilot clients and sessions programmatically
    • How to stream assistant responses in real time
    • How to define type-safe C# tools that the agent can invoke
    • How to build a repeatable, multi-turn workflow around repository data

    What You'll Build

    Release notes are useful, but turning a pile of commits into a clear, categorized changelog is tedious. The tool in this lab automates that job and provides a reusable pattern for any .NET application that needs an agentic workflow.

    FeatureWhat it does
    Git history analysisReads commits between tags, SHAs, branches, or relative refs
    Categorized outputProduces Features, Bug Fixes, Breaking Changes, and Maintenance sections
    Real-time streamingWrites assistant response chunks as they arrive
    Custom toolsGives Copilot get_git_log and read_file capabilities
    Interactive follow-upsContinues the same conversation after the first changelog

    When finished, you will run:

    dotnet run -- HEAD~10 HEAD

    and receive a streamed changelog in your terminal.

    Concepts

    Background: What Is the Copilot SDK?

    The GitHub Copilot SDK is a multi-platform library for programmatic control of GitHub Copilot CLI. Rather than interacting through an editor or terminal, your application creates a client, opens a session, sends prompts, receives events, and supplies tools.

    How It Works

    Your .NET application
        |
        v
GitHub.Copilot.SDK client  -- JSON-RPC -->  Copilot CLI agent runtime
        ^                                      |
        |                                      v
        +----------- events and tool results - LLM, planning, execution

    By default, the .NET SDK manages the local Copilot runtime lifecycle for you. Your application owns the workflow and tool handlers; the runtime owns model routing, planning, and the agent loop.

    Key Concepts

    ConceptDescription
    ClientThe entry point that starts, monitors, and stops the Copilot runtime.
    SessionA conversation context with prompts, events, tool calls, and history.
    ToolsType-safe C# functions that Copilot can invoke to gather data or perform work.
    EventsTyped notifications such as AssistantMessageDeltaEvent and SessionIdleEvent.
    BYOKBring Your Own Key: configure a supported provider instead of GitHub authentication.

    Available SDKs

    Prerequisites

    • .NET SDK 10.0: verify with dotnet --version.
    • Git: verify with git --version.
    • GitHub Copilot access, or a supported BYOK provider.
    • Copilot CLI authentication for standard GitHub usage. The .NET SDK bundles the runtime, but your account still needs to be authenticated.
    • A Git repository with enough history to analyze. Any repository works.

    Step 2

    Hello Copilot SDK

    Replace Program.cs with this minimal client and session:

    using GitHub.Copilot;

await using var client = new CopilotClient();
await client.StartAsync();

await using var session = await client.CreateSessionAsync(new SessionConfig
{
    Model = "auto",
    OnPermissionRequest = PermissionHandler.ApproveAll
});

var done = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);

using var subscription = session.On<SessionEvent>(evt =>
{
    switch (evt)
    {
        case AssistantMessageEvent message:
            Console.WriteLine(message.Data.Content);
            break;
        case SessionIdleEvent:
            done.TrySetResult();
            break;
        case SessionErrorEvent error:
            done.TrySetException(new InvalidOperationException(error.Data.Message));
            break;
    }
});

await session.SendAsync(new MessageOptions
{
    Prompt = "In one sentence, what makes a good changelog?"
});

await done.Task;

    Run it:

    dotnet run

    You should see one concise answer. The client starts the local runtime, the session creates a conversation, SendAsync sends the prompt, and SessionIdleEvent gives the application a reliable completion signal.

    Why not call SendAndWaitAsync?The current .NET README documents SendAsync plus the session idle event as the stable completion pattern. This also prepares the app for streaming in the next step.
    Step 3

    Add Real-Time Streaming

    Enable Streaming = true and handle typed delta events. Create StreamExample.cs, or replace Program.cs temporarily:

    using GitHub.Copilot;

await using var client = new CopilotClient();
await client.StartAsync();

await using var session = await client.CreateSessionAsync(new SessionConfig
{
    Model = "auto",
    Streaming = true,
    OnPermissionRequest = PermissionHandler.ApproveAll
});

var done = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);

using var subscription = session.On<SessionEvent>(evt =>
{
    switch (evt)
    {
        case AssistantMessageDeltaEvent delta:
            Console.Write(delta.Data.DeltaContent);
            break;
        case SessionIdleEvent:
            Console.WriteLine("\n--- Done ---");
            done.TrySetResult();
            break;
        case SessionErrorEvent error:
            done.TrySetException(new InvalidOperationException(error.Data.Message));
            break;
    }
});

await session.SendAsync(new MessageOptions
{
    Prompt = "Write a short, professional changelog entry for a feature that adds dark mode support."
});

await done.Task;

    Run it with dotnet run. The response should appear incrementally rather than arriving as one large block.

    EventWhen it firesTypical use
    AssistantMessageDeltaEventFor each response chunkWrite text to the terminal
    AssistantMessageEventFor the complete assistant messageCapture or inspect final content
    SessionIdleEventWhen the agent has finished processingRelease a waiter or show a prompt
    SessionErrorEventWhen the session reports an errorFail clearly and clean up
    Step 4

    Define Custom Tools

    Custom tools let Copilot call code that belongs to your application. The current .NET SDK uses CopilotTool.DefineTool, Microsoft.Extensions.AI metadata, and a type-safe handler.

    Try this focused example before building the full generator:

    using GitHub.Copilot;
using Microsoft.Extensions.AI;
using System.ComponentModel;

var getWeather = CopilotTool.DefineTool(
    ([Description("The city name")] string city) =>
    {
        var conditions = new[] { "sunny", "cloudy", "rainy", "partly cloudy" };
        var temperature = Random.Shared.Next(50, 80);
        var condition = conditions[Random.Shared.Next(conditions.Length)];
        return new { city, temperature = $"{temperature} F", condition };
    },
    factoryOptions: new AIFunctionFactoryOptions
    {
        Name = "get_weather",
        Description = "Get the current weather for a city"
    });

await using var client = new CopilotClient();
await client.StartAsync();
await using var session = await client.CreateSessionAsync(new SessionConfig
{
    Model = "auto",
    Streaming = true,
    OnPermissionRequest = PermissionHandler.ApproveAll,
    Tools = [getWeather]
});

using var subscription = session.On<SessionEvent>(evt =>
{
    if (evt is AssistantMessageDeltaEvent delta)
        Console.Write(delta.Data.DeltaContent);
    else if (evt is SessionIdleEvent)
        Console.WriteLine();
});

await session.SendAsync(new MessageOptions
{
    Prompt = "What's the weather like in Seattle and Tokyo? Use the weather tool."
});

    Run it and watch for the agent to invoke get_weather before composing its answer.

    How tool calling works
    1. The tool name and description tell Copilot what capability exists.
    2. The parameter annotation contributes a schema for the handler input.
    3. Copilot decides when the tool is relevant.
    4. The SDK invokes your handler and returns its JSON-serializable result to the runtime.
    5. The model uses that result in the next response step.
    Step 5

    Build the Changelog Generator

    Now combine the client, streaming events, and two repository tools. This version uses Process instead of shell string interpolation, which avoids treating a ref or path as executable command text.

    Replace Program.cs with the following complete implementation:

    using GitHub.Copilot;
using Microsoft.Extensions.AI;
using System.ComponentModel;
using System.Diagnostics;
using System.Text;

var arguments = Environment.GetCommandLineArgs().Skip(1).ToArray();
if (arguments.Length < 2)
{
    Console.Error.WriteLine("Usage: dotnet run -- <from-ref> <to-ref> [repo-path]");
    Console.Error.WriteLine("Example: dotnet run -- HEAD~10 HEAD");
    return 1;
}

var fromRef = arguments[0];
var toRef = arguments[1];
var repoPath = Path.GetFullPath(arguments.ElementAtOrDefault(2) ?? ".");
var refRange = $"{fromRef}..{toRef}";

Console.WriteLine($"\nGenerating changelog for {refRange} in {repoPath}\n");

var getGitLog = CopilotTool.DefineTool(
    ([Description("A git ref range, such as v1.0.0..v2.0.0")] string? refRange,
     [Description("Maximum number of commits to return")] int maxCount = 100) =>
    {
        var result = RunGit(repoPath, "log", refRange, "--pretty=format:%h|%s|%an|%ad",
            "--date=short", "-n", Math.Clamp(maxCount, 1, 500).ToString());
        return result.ExitCode == 0
            ? result.Output
            : $"Git log failed: {result.Error}";
    },
    factoryOptions: new AIFunctionFactoryOptions
    {
        Name = "get_git_log",
        Description = "Get commits from a repository, optionally filtered by a ref range."
    });

var readFile = CopilotTool.DefineTool(
    ([Description("A path relative to the repository root")] string filePath) =>
    {
        var fullPath = Path.GetFullPath(Path.Combine(repoPath, filePath));
        if (!fullPath.StartsWith(repoPath, StringComparison.OrdinalIgnoreCase))
            return "Rejected: the path must stay inside the repository.";
        if (!File.Exists(fullPath))
            return $"File not found: {filePath}";

        var content = File.ReadAllText(fullPath);
        return content.Length > 10000
            ? content[..10000] + "\n... [truncated]"
            : content;
    },
    factoryOptions: new AIFunctionFactoryOptions
    {
        Name = "read_file",
        Description = "Read a text file from the repository for additional change context."
    });

await using var client = new CopilotClient();
await client.StartAsync();
await using var session = await client.CreateSessionAsync(new SessionConfig
{
    Model = "auto",
    Streaming = true,
    OnPermissionRequest = PermissionHandler.ApproveAll,
    Tools = [getGitLog, readFile]
});

var finalContent = new StringBuilder();
var done = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);

using var subscription = session.On<SessionEvent>(evt =>
{
    switch (evt)
    {
        case AssistantMessageDeltaEvent delta:
            Console.Write(delta.Data.DeltaContent);
            finalContent.Append(delta.Data.DeltaContent);
            break;
        case SessionIdleEvent:
            Console.WriteLine();
            done.TrySetResult();
            break;
        case SessionErrorEvent error:
            done.TrySetException(new InvalidOperationException(error.Data.Message));
            break;
    }
});

await session.SendAsync(new MessageOptions
{
    Prompt = $"""
        You are a release-notes writer. Use get_git_log to retrieve commits in "{refRange}".
        Then write Markdown with these sections when they have relevant commits:
        - Summary: a 2-3 sentence overview.
        - Features: new capabilities.
        - Bug Fixes: issues resolved.
        - Breaking Changes: anything requiring user action.
        - Maintenance: refactoring, dependencies, CI, and documentation.

        Group related commits. Write from the user's perspective. Include each commit hash.
        Use read_file when a commit needs more context. Do not invent changes.
        """
});

await done.Task;
var content = finalContent.ToString();
if (!content.Contains("Summary", StringComparison.OrdinalIgnoreCase) &&
    !content.Contains("##", StringComparison.Ordinal))
{
    Console.Error.WriteLine("The response did not look like a changelog.");
    return 1;
}

Console.WriteLine("\nChangelog generated.\n");
return 0;

static (int ExitCode, string Output, string Error) RunGit(string workingDirectory, params string[] arguments)
{
    var startInfo = new ProcessStartInfo("git")
    {
        WorkingDirectory = workingDirectory,
        RedirectStandardOutput = true,
        RedirectStandardError = true,
        UseShellExecute = false,
        CreateNoWindow = true
    };
    foreach (var argument in arguments)
        startInfo.ArgumentList.Add(argument);

    using var process = Process.Start(startInfo)!;
    var output = process.StandardOutput.ReadToEnd();
    var error = process.StandardError.ReadToEnd();
    process.WaitForExit();
    return (process.ExitCode, output, error);
}

    Build and run against the current repository:

    dotnet build
dotnet run -- HEAD~5 HEAD

    To analyze another repository, pass its path:

    dotnet run -- HEAD~10 HEAD ..\my-other-project
    CheckpointThe agent should call get_git_log, optionally call read_file, and stream a categorized Markdown changelog. If the tool is not called, make the prompt explicit about which tool contains the needed data.

    Try it with release tags

    git tag --sort=-creatordate
dotnet run -- v1.0.0 v2.0.0

    Relative refs such as HEAD~5 HEAD are usually the easiest first test because they work in any repository with enough commits.

    Step 6

    Interactive Follow-Ups

    A session remains alive after the first answer. Add an input loop so users can ask questions about the same commits without reloading the repository context.

    First add this helper near the other local variables:

    static async Task<string?> ReadLineAsync()
{
    return await Console.In.ReadLineAsync();
}

    Then replace the final success message and return 0; with:

    Console.WriteLine("\nChangelog generated. Ask a follow-up, or type 'quit'.\n");
while (true)
{
    Console.Write("Follow-up: ");
    var input = await ReadLineAsync();
    if (string.IsNullOrWhiteSpace(input) ||
        input.Equals("quit", StringComparison.OrdinalIgnoreCase))
        break;

    finalContent.Clear();
    done = new TaskCompletionSource(TaskCreationOptions.RunContinuationsAsynchronously);
    await session.SendAsync(new MessageOptions { Prompt = input });
    await done.Task;
    Console.WriteLine();
}

Console.WriteLine("Goodbye!");
return 0;

    Run it again and try:

    dotnet run -- HEAD~10 HEAD

Follow-up: Which commits affect the API?
Follow-up: Rewrite the summary for a non-technical audience
Follow-up: quit
    Why this is usefulThe session retains the conversation and the model's prior tool results. Follow-up prompts can refer to “those commits” without asking your tools to repeat the entire first analysis.
    Step 7

    Wrap-Up & Next Steps

    You have built a functional .NET CLI application powered by the GitHub Copilot SDK. It creates a client and session, sends prompts, streams responses, exposes custom repository tools, and supports multi-turn conversation.

    ExtensionDifficultyWhat you'll practice
    Add a get_diff tool for commit patchesEasyDeeper tool definitions and output limits
    Run on a tag push in CIMediumHeadless SDK usage and release automation
    Support JSON or HTML outputMediumStructured response prompting and validation
    Add a search_issues toolAdvancedAuthenticated API integration
    Connect to an MCP serverAdvancedExternal tools and service discovery
    Production checklistReplace ApproveAll with a policy-aware handler, validate every path and process argument, cap tool output, handle cancellation and timeouts, avoid logging secrets, and pin or regularly review your SDK package version.
    Bonus

    Export to a Markdown File

    The complete response is already accumulated in finalContent. Save it after the success check and before the follow-up loop:

    var outputPath = Path.Combine(Directory.GetCurrentDirectory(), "CHANGELOG.md");
await File.WriteAllTextAsync(outputPath, finalContent.ToString());
Console.WriteLine($"Saved to {outputPath}");

    Now each successful run produces both terminal output and a CHANGELOG.md file that can be reviewed and committed.
