GitHub Copilot CLI

Ask Copilot to explore a repository, explain a command, plan a change, and take action from the terminal while you keep control of the tools it can use.

Start and navigate

Install and launch

npm install -g @github/copilot

# Start in a repository
cd path/to/repo
copilot

Permissions and execution

Permission modes

AskConfirm tool use as it is requested.
AllowPre-approve a specific tool or command.
DenyBlock a tool, path, or operation.
AutopilotLet Copilot continue through a task with fewer prompts.
Good default: begin in ask mode, allow only the tools needed for the current task, and inspect the diff before committing.

Run with explicit boundaries

# Non-interactive prompt
copilot -p "explain the test failure"

# Permit a named tool for this run
copilot -p "run the unit tests" \\
  --allow-tool 'shell(npm test)'

# Block a tool when scripting
copilot -p "summarize the repo" \\
  --deny-tool 'shell(git push)'

Repeatable workflows

Understand a codebase

copilot
> map the architecture of this repo
> trace the login request end to end
> identify the highest-risk dependency

Plan, then implement

copilot
> /plan add CSV export to the report view
> implement the plan
> run the focused tests
> /review

Investigate a failure

copilot
> reproduce the failing test
> explain the root cause
> propose the smallest fix
> apply it and verify the test

Prompt patterns

Prompts that create useful constraints

ExploreInspect the existing patterns first. Report the files you would change and why.
ImplementImplement this behavior without changing the public API. Follow the nearest existing example.
TestAdd focused tests for the happy path, invalid input, and the boundary case. Run only the relevant suite.
ReviewReview the current diff for correctness, security, backward compatibility, and missing tests.

Context worth supplying

GoalWhat outcome should change?
ScopeWhich files, service, or command is in bounds?
ConstraintsAPI compatibility, runtime, style, or performance rules.
EvidenceError output, failing test, sample input, or expected result.
CheckExact test, lint, build, or command that proves it works.

Safety checklist

Before execution

1Confirm the working directory.
2Check the proposed files and commands.
3Keep secrets and personal data out of prompts.

Before commit

1Inspect git diff and git status.
2Run focused tests and review failures.
3Check generated dependencies and configuration.

Remember

RuleCopilot proposes; you authorize.
RuleSmall, verifiable steps beat broad autonomous changes.
RuleUse /clear when context starts to drift.
