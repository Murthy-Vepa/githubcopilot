🧭 Before You Begin

Use a small, disposable project or a safe branch of your own repository. The exercises are designed to build understanding before action.

For every exercise, distinguish Copilot's suggestion from verified facts. Record assumptions, think about context and token use, protect sensitive data, and involve a human reviewer when a decision affects users, security, or production systems.

EX 01 Auto-Completion: Suggestions and Context ⏱ 15 min ▼
Goal
Understand how auto-completion uses local context to predict code or text, and why every suggestion still needs human verification.
  1. 1
    Open a non-sensitive sample file and pause before typing. List what context is visible to Copilot: nearby code, file name, open tabs, and your instruction.
  2. 2
    Type a neutral comment and wait for a suggestion:
    // Return a concise summary of this function
  3. 3
    Observe the suggestion without accepting it. Note which parts appear grounded in the file and which parts are assumptions.
  4. 4
    Cycle through alternatives with Alt+] and compare specificity, confidence, and risk.
  5. 5
    Accept only a harmless suggestion, then verify it against the surrounding code. Do not use generated text as evidence by itself.
  6. 6
    Discuss: Identify one reason a plausible completion could still be wrong or unsafe.
💡Ghost text turns orange when Copilot detects a possible security concern. Always review before accepting.
Validation Checklist
✓
Identified the context available to an inline completion
✓
Compared alternatives instead of accepting the first suggestion
✓
Verified the accepted explanation against the source
EX 02 Copilot Chat: Ask, Inspect, Refine ⏱ 10 min ▼
Goal
Use Copilot Chat to ask a question, inspect the response, and refine the request without treating Chat as an authority.
  1. 1
    Ask Copilot in inline chat: Explain what this function does. Save the response without accepting changes.
  2. 2
    Ask the same question again with constraints:
    Explain this function in three bullet points. Identify one assumption, one edge case, and the exact line that supports each observation. Do not modify files.
  3. 3
    Compare both responses for unsupported claims, missing context, and useful evidence.
  4. 4
    Ask Copilot what additional file or test would reduce its uncertainty. Verify that suggestion against the repository.
  5. 5
    Record one Chat question that made the response more precise and one claim that still requires independent verification.
Validation Checklist
✓
Compared vague and constrained prompts using the same code
✓
Separated evidence from assumptions in both responses
✓
Recorded one prompt improvement and one remaining uncertainty
EX 03 Copilot Chat: Context and Grounding ⏱ 15 min ▼
Goal
Learn how selected files, conversation history, and repository context affect a Chat response and its level of confidence.

Task 3a — Minimal context

Explain this function and identify one uncertainty. Use only the selected file. Do not edit files.

Task 3b — Add context

Now use the selected file and its nearest test or documentation file. Explain the function, cite evidence, and list what remains unknown. Do not edit files.

Task 3c — Compare

Compare both responses. Identify which claims became better grounded and which claims are still assumptions.
💡More context can improve grounding, but it also consumes tokens and may include information that is unnecessary or sensitive.
Validation Checklist
✓
Compared a response with minimal and expanded context
✓
Separated grounded claims from assumptions
✓
Identified unnecessary or sensitive context to exclude
EX 04 Model Selection: Match Model to Task ⏱ 10 min ▼
Goal
Compare model choices using task complexity, response quality, latency, availability, and cost rather than choosing by habit.

Compare the task profiles

Fast model: short explanation, simple transformation, quick iteration
More capable model: ambiguous reasoning, larger context, difficult review
Auto-completion: low-latency local suggestion while typing
Chat: conversational explanation, comparison, or planning

Record the trade-offs

For each task, ask:
What quality is required?
How much latency is acceptable?
How much context is necessary?
What is the lowest-cost option that meets the need?
⚡Model choice is a trade-off, not a permanent label. Re-evaluate it when quality, latency, context, or cost requirements change.
Validation Checklist
✓
Matched model and Copilot surface choices to task needs
✓
Documented quality, latency, context, and cost trade-offs
EX 05 Token Economics: Count the Context ⏱ 10 min ▼
Goal
Understand how input context, output length, repeated turns, and model choice influence token consumption and usage cost.
  1. 1
    Choose one Chat task and list its inputs: user request, selected files, conversation history, instructions, and expected response.
  2. 2
    Mark which inputs are necessary, useful but optional, or unnecessary. Estimate which ones contribute most to context size.
  3. 3
    Compare a concise request with a context-heavy request. Record the change in response quality, latency, and likely token use.
  4. 4
    Write one token-saving improvement that preserves the information needed for a reliable answer.
⚠️More context is not automatically better. Large, repeated, or irrelevant context can increase cost and make the useful signal harder to find.
Validation Checklist
✓
Separated necessary, optional, and unnecessary context
✓
Compared context size with quality and latency trade-offs
✓
Recorded one practical token-saving improvement
EX 06 Responsible AI: Verify Chat and Completion Output ⏱ 10 min ▼
Goal
Practice human review of Copilot Chat responses and auto-completions for correctness, security, and maintainability.
  1. 1
    Ask Chat to explain a small, non-sensitive example and ask auto-completion to suggest a harmless comment or expression.
  2. 2
    Check each result against the source, expected behavior, security assumptions, and project conventions.
  3. 3
    Record one correct claim, one incomplete claim, and one plausible but unsupported claim.
  4. 4
    Decide what evidence a human must review before using the result in a real change.

Recorded correct, incomplete, and unsupported claims

EX 07 Token Economics: Manage Conversation Cost ⏱ 10 min ▼
Goal
Understand how conversation history, repeated prompts, response length, and model choice affect token usage and practical cost.
  1. 1
    Start a short Chat task and record the initial request, selected context, response length, and model used if shown.
  2. 2
    Continue the conversation with two follow-up questions. Note which earlier context is repeated or carried forward.
  3. 3
    Repeat the task in a fresh conversation with a concise request and only the necessary context.
  4. 4
    Compare the two approaches for usefulness, response length, latency, and likely token consumption. Record when starting a new conversation is preferable.
Validation Checklist

✓
Recorded response length, latency, and likely token drivers

EX 08 Responsible AI: Privacy and Security Controls ⏱ 10 min ▼
Goal
Design practical controls for privacy, security, data minimization, permissions, and auditability when using Copilot.
  1. 1
    Create a risk register with the columns: asset, threat, likelihood, impact, control, owner, and evidence.
  2. 2
    Add at least one risk for sensitive source data, insecure generated content, excessive tool permissions, and untraceable decisions.
  3. 3
    For each risk, propose a control such as redaction, least privilege, human approval, secure review, logging, or retention limits.
  4. 4
    Choose the highest-impact risk and explain how you would test that the control works.
💡A control is stronger when it has an owner, an observable signal, and a response when the control fails.
Validation Checklist
✓
Risk register covers privacy, security, permissions, and accountability
✓
Each risk has a concrete control and an accountable owner
✓
Defined evidence for testing the highest-impact control
EX 09 Responsible AI: Hallucination, Bias, and Copyright ⏱ 10 min ▼
Goal
Recognize common risks in Copilot output and practice checking factual claims, fairness, attribution, and potential copyright concerns.
  1. 1
    Ask Chat for a short explanation of a familiar topic and highlight every factual claim that needs checking.
  2. 2
    Ask Copilot to suggest wording for two audiences with different needs. Check whether assumptions or stereotypes affect the result.
  3. 3
    Review generated code or prose for copied-looking material, missing attribution, license concerns, and unsafe reuse.
  4. 4
    For each risk, record the verification method: source check, peer review, accessibility check, license review, or subject-matter review.
Validation Checklist
✓
Flagged factual claims that require independent verification
✓
Considered bias and audience impact
✓
Completed a copyright, attribution, or license review
EX 10 Responsible AI: Privacy and Human Oversight ⏱ 10 min ▼
Goal
Design a safe review process for Copilot use that protects sensitive information and keeps consequential decisions with people.
  1. 1
    List the types of information that should never be pasted into a Copilot request for your scenario.
  2. 2
    Define a redaction or minimization step before Chat or auto-completion receives context.
  3. 3
    Add review checkpoints for generated code, user-facing text, security-sensitive content, and decisions affecting people.
  4. 4
    Specify what should be recorded for accountability and what action to take when the review fails.
⚠️Copilot can assist with a decision without owning it. People remain responsible for checking, approving, and correcting consequential output.

Identified prohibited or sensitive information
✓
Added minimization, review, and accountability checkpoints

EX 11 Responsible AI: Scenario Decision Lab ⏱ 15 min ▼
Goal
Apply responsible AI principles to realistic Copilot scenarios and make a documented allow, restrict, or escalate decision.
  1. 1
    Choose one scenario: summarizing private records, generating user-facing content, completing code, selecting a model, or reviewing security-sensitive code.
  2. 2
    Assess purpose, affected people, data sensitivity, potential harm, bias, copyright, permissions, and reversibility.
  3. 3
    Choose allow, restrict, or escalate. List the minimum controls and human evidence required.
  4. 4
    Present the decision to a partner. Update it when they identify a missing risk or a weaker assumption.
Decision record: Scenario, affected people, data, risks, decision, controls, owner, evidence, escalation trigger.
