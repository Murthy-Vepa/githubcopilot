01

Model choice is a task decision

There is no single best model for every prompt. The useful question is what kind of work you are asking Copilot to do.

Start with Auto when you are unsure. Copilot can select an appropriate model based on availability and task complexity. Model usage can consume AI credits at different rates, so check your plan's pricing and limits.
Speed

For syntax questions, small edits, and repetitive changes, latency may matter more than maximum reasoning depth.

Reasoning

For architecture, multi-file refactors, debugging, and trade-offs, a deeper reasoning model may save time overall.

Context

For large codebases or long investigations, choose a model suited to sustained context and tool-driven work.

Input type

For screenshots, diagrams, and UI components, use a model that supports visual input in the surface you are using.

02

Quick selector

Use the shortest path to a reasonable first choice.

I need a small, fast answer

Try Claude Haiku 4.5, MAI-Code-1-Flash, or another fast model available in your Copilot surface.

I am writing or reviewing everyday code

Try GPT-5 mini, GPT-5.3-Codex, MAI-Code-1-Flash, Raptor mini, or Claude Sonnet 4.6.

I am debugging or changing architecture

Try GPT-5.5, Claude Opus 4.7, Claude Sonnet 4.6, Gemini 3.1 Pro, or another deep-reasoning option.

I need to understand a screenshot or diagram

Choose a model with visual input support, such as GPT-5 mini, Claude Sonnet 4.6, or Gemini 3.1 Pro, where available.

Good for

Raptor mini

05

Fast help with simple or repetitive tasks

Optimize for responsiveness when the work is small, familiar, and easy to verify.

  • Write or edit a small function or utility.
  • Ask a syntax or language question.
  • Prototype an idea with minimal setup.
  • Get quick feedback on a simple edit.
Claude Haiku 4.5

Balances fast responses with useful quality for lightweight coding questions.

MAI-Code-1-Flash

Handles quick coding tasks with adaptive efficiency and concise output.

Do not optimize only for speed: if the cost of a wrong answer is high, use a stronger model or ask for a verification step.
06

Deep reasoning and debugging

Use this lane when the answer depends on multiple files, competing trade-offs, or a careful chain of reasoning.

  • Debug complex issues with context across multiple files.
  • Refactor large or interconnected codebases.
  • Plan features or architecture across layers.
  • Analyze logs, performance data, or system behavior.
GPT-5.5

Complex reasoning, code analysis, and technical decision-making.

Claude Opus 4.7

Sophisticated reasoning for difficult problem-solving challenges.

Claude Sonnet 4.6

Strong general reasoning and reliable completions under pressure.

Gemini 3.1 Pro

Effective edit-then-test loops with high tool precision.

07

Working with visuals

Choose a multimodal model when the input is a screenshot, diagram, or UI component rather than text alone.

Ask about screenshots

Use visual input to identify layout issues, visible errors, states, and interaction problems.

Review diagrams

Ask Copilot to explain relationships, find inconsistencies, or turn a visual into implementation tasks.

Inspect UI components

Use a screenshot as context for accessibility, responsive behavior, and visual debugging.

Check the surface

Visual reasoning only helps when the editor, chat surface, and selected model support image input.

08

A practical selection workflow

Make model choice part of the engineering loop, not a separate ceremony.

1. Classify the task

Fast edit, everyday coding, deep reasoning, agentic work, or visual analysis?

2. Choose a first model

Use the task lane above or start with Auto when availability and complexity are uncertain.

3. Add the right context

Give Copilot the relevant files, error output, requirements, tests, and constraints.

4. Verify the result

Run tests, inspect the diff, check security implications, and confirm the output matches the requirement.

Model choice does not replace judgment. A stronger model can produce a more useful first attempt, but the developer still owns the review, test evidence, security decision, and final change.
