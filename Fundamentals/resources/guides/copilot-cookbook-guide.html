Orientation

The Cookbook is a set of concrete, repeatable ways to ask GitHub Copilot for help with everyday development work.

The useful habit: give Copilot enough context to reason about the task, ask for a plan before a broad change, and verify the result with tests, a diff, or a second review.
Choose a recipe

Start with the closest task: explain, debug, generate, refactor, document, test, or secure.

Shape the prompt

Name the files, constraints, expected behavior, output format, and edge cases that matter.

Check the result

Review generated code and run the project tools that can confirm correctness, safety, and maintainability.

Remember: the examples are starting points. Copilot responses are non-deterministic, so adapt each prompt to your repository, policies, and technology stack.

Review checklist

Use this short check after any Cookbook recipe that produces code, configuration, documentation, or a decision.

Context

Did Copilot use the right files, issue, requirements, style guide, and project conventions?

Correctness

Does the output preserve existing behavior and cover success, failure, boundary, and integration cases?

Security

Are input validation, authorization, secrets, privacy, dependencies, and error paths handled safely?

Maintainability

Is the change understandable, focused, testable, and consistent with the surrounding code?

Evidence

What test, lint, scan, benchmark, or rendered preview confirms the result?

Human decision

What assumption or tradeoff still needs a developer, reviewer, or product owner to decide?

A good Copilot session ends with evidence: a passing check, a reviewed diff, a documented decision, or a clear next action.
