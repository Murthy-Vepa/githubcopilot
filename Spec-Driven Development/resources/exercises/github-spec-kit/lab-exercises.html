EX 01 Generate the Constitution ⏱ 10 min ▼
Goal
Generate constitution.md — the shared architectural baseline all agents follow. Every subsequent exercise builds on this foundation.
  1. 1
    Open Chat panel and run:
    @constitution-generator scan this repository and generate a constitution.md at .github/memory/constitution.md. Focus on the .NET 10 stack, repository pattern, and test structure.
  2. 2
    Review the generated file. Verify it captures: tech stack, folder conventions, naming rules, repository pattern, security requirements.
  3. 3
    Make any corrections directly in the file, then add at the top:
    # Ratified: [Your Name], 2026-07-09
Validation Checklist
✓
.github/memory/constitution.md created
✓
Tech stack (.NET 10, EF Core, xUnit) correctly identified
✓
Repository pattern convention is captured
✓
File ratified with your name
EX 02 Write a Spec from a User Story ⏱ 20 min ▼
Goal
Use the Planner agent to turn a vague user story into a structured spec.md with testable REQ-XXX requirements. Experience the clarifying questions workflow.
User Story
"As a user, I want to mark individual todos as high priority so I can focus on the most important items first."
  1. 1
    Create the folder: .github/specs/todo-priority/
  2. 2
    Invoke the planner:
    @planner "Add a priority field to TodoItems. Users should be able to set priority (Low/Medium/High) when creating or editing a todo. The Index page should show priority with a visual indicator. Users should be able to filter by priority."
  3. 3
    Answer the planner's clarifying questions. Common ones: default value? sort order? filter "All" option? Required or optional?
  4. 4
    Run Gate 1 check on the generated spec:
    @workspace review .github/specs/todo-priority/spec.md against Gate 1 criteria: every REQ-XXX must have a testable acceptance criterion, no ambiguous language, out-of-scope section must be present
  5. 5
    Fix any issues found, then approve: @planner approved, proceed to plan.md
🔒Gate 1 is the most important gate. A two-minute review here prevents hours of rework. Look for: "works correctly", "handles errors", or any other vague language.
Validation Checklist
✓
spec.md created with at least 3 REQ-XXX requirements
✓
Each requirement has a concrete acceptance criterion
✓
Out-of-scope section is present and specific
✓
Gate 1 check passes (all criteria met)
EX 03 Generate plan.md & tasks.json ⏱ 20 min ▼
Goal
Turn the approved spec into an executable implementation plan and machine-readable task list. Run Gate 2 to verify 100% requirement coverage.
  1. 1
    After approving the spec, the planner generates plan.md. Check: does every REQ-XXX from spec.md appear in at least one step?
  2. 2
    Run Gate 2 coverage check:
    @workspace check that .github/specs/todo-priority/plan.md covers all REQ-XXX requirements from .github/specs/todo-priority/spec.md
  3. 3
    If gaps are found, ask the planner to add the missing steps. If Gate 2 passes, approve the plan.
  4. 4
    Ask for task decomposition:
    @planner generate tasks.json from .github/specs/todo-priority/plan.md. Assign agent types: coder for implementation, tester for tests.
  5. 5
    Review tasks.json: Are dependency chains correct? Is each task small (one file/method)? Are test tasks included?
Validation Checklist
✓
plan.md created with steps linked to REQ-XXX
✓
Gate 2 check shows 100% requirement coverage
✓
tasks.json generated with correct structure (id, agent, reqs, depends, status)
✓
Dependency graph is acyclic (no circular deps)
EX 04 Feature Inventory of Existing App ⏱ 15 min ▼
Goal
Use the feature inventory skill to catalogue what the TodoApp currently does as structured REQ-XXX requirements — essential before any migration or refactoring work.
  1. 1
    In Chat panel:
    @workspace inventory all user-facing features of the TodoApp application. Output as REQ-XXX requirements with acceptance criteria. Focus on what a user can actually do in the UI.
  2. 2
    Save the output to .github/specs/existing-features/spec.md
  3. 3
    Run coverage gap analysis:
    @workspace are there any features in .github/specs/existing-features/spec.md that do NOT have test coverage in src/TodoApp.Tests/?
💡This technique is especially powerful before migrations — you get a requirements doc for a system that probably never had one.
Validation Checklist
✓
Feature inventory created with REQ-XXX format
✓
At least 4 features identified (Create, Read, Update, Delete)
✓
Coverage gap analysis identifies any untested features
EX 05Automate the Quality Gates⏱ 15 min▼
Goal
Run specification quality and traceability checks as repeatable commands instead of a one-time manual review.
  1. 1
    Run the quality-gate workflow on spec.md and record every finding.
  2. 2
    Fix one deliberately vague acceptance criterion, then rerun the spec-quality gate.
  3. 3
    Run the spec-to-plan and plan-to-tasks checks and compare their requirement mappings.
  4. 4
    Save the output to .github/specs/todo-priority/gate-report.md.
Validation Checklist
✓
All applicable quality gates were run
✓
At least one ambiguous criterion was fixed
✓
Gate report is saved with findings and final status
EX 06Execute with Requirement Traceability⏱ 20 min▼
Goal
Take one approved task from tasks.json through implementation and prove which requirement, files, and tests it satisfies.
  1. 1
    Select the smallest unblocked task and note its REQ-XXX references and acceptance criteria.
  2. 2
    Ask the coder to implement only that task, preserving the constitution and repository conventions.
  3. 3
    Ask the tester to add or run focused tests for the same requirement.
  4. 4
    Record the requirement-to-file-to-test mapping in the task report and run the build.
Validation Checklist
✓
Only an unblocked task was executed
✓
Requirement, changed files, and tests are traceable
✓
Focused tests and build pass
⭐ Bonus — Manual Quality Gate Review
Practice the Gate 1 checklist manually on your spec.md:

☐ Every REQ-XXX has at least one testable acceptance criterion
☐ No ambiguous language ("works correctly", "is fast", "handles errors" without specifics)
☐ Out-of-scope section is non-empty and specific
☐ No unresolved open questions

Then do Gate 2 manually: list every REQ-XXX from spec.md and find each one in plan.md. If any are missing, add a plan step.

🎉 Session 3 Lab Complete!

You have constitution, spec, plan, and tasks ready. Bring them to Session 4 — the Agent Squad capstone!
