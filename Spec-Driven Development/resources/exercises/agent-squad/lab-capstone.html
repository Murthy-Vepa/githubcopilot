Agent Squad
Capstone

Ship a real feature using the full autonomous pipeline. No manual coding — just describe, review gates, and approve the PR.

⏱ 115 min
Sessions 1–3 required
🏆 Badge on completion
🎯 Your Mission

Add Priority to TodoItems — End to End

Add a Priority field (Low / Medium / High) to TodoItems with a colour-coded badge on the Index page, priority selection on Create/Edit, and filtering. All layers: model, migration, service, pages, tests, docs.

→Write zero lines of code manually — give instructions and approve gates
→Review every agent output before approving each gate
→Complete within 115 minutes
Orchestrator→ Planner→ 👤 Gate 1→ Coder→ Tester→ Reviewer→ Security→ SRE→ Docs→ 👤 Gate 2 → PR

PHASE 1 Setup — Verify Readiness ⏱ 10 min ▼
  1. 1
    Verify constitution.md exists:
    @workspace does .github/memory/constitution.md exist and is it accurate?
    If missing, run @constitution-generator scan this repo
  2. 2
    Create the spec folder: mkdir .github/specs/todo-priority
  3. 3
    Verify a clean build and all tests pass:
    dotnet build src/TodoApp/TodoApp.csproj --nologo -q
    dotnet test src/TodoApp.Tests/TodoApp.Tests.csproj --nologo -q
Checks
✓
constitution.md exists and is accurate
✓
Spec folder created
✓

PHASE 2 Spec — Planner & Gate 1 ⏱ 15 min ▼
  1. 1
    Invoke the Planner:
    @planner "Add a Priority field to TodoItems. Priority values are: Low, Medium, High. Users can set priority on Create and Edit. Index shows a colour-coded badge (Low=blue, Medium=yellow, High=red). Users can filter by priority. Priority defaults to Medium."
  2. 2
    Answer all clarifying questions from the planner before it writes spec.md.
  3. 3
    Review spec.md and run Gate 1:
    @workspace run Gate 1 quality check on .github/specs/todo-priority/spec.md
🔒
Gate 1 — Spec Approval (You)
Read spec.md. Every REQ-XXX must have a testable acceptance criterion. Out-of-scope section must be present. No ambiguous language. Approve or request changes.
Checks
✓

✓

PHASE 3 Plan & Tasks — Gates 2 & 3 ⏱ 15 min ▼
  1. 1
    Approve spec and review generated plan.md. Check: EF Core migration step included? All 4 user actions covered? Technical approach uses EF Core enum?
  2. 2
    Run Gate 2:
    @workspace verify .github/specs/todo-priority/plan.md covers all REQ-XXX from spec.md
  3. 3
    After plan approval, generate tasks.json and run Gate 3:
    @workspace validate .github/specs/todo-priority/tasks.json — check dependency graph and completeness
Checks

✓

PHASE 4 Execute — Watch the Pipeline Run ⏱ 40 min ▼
  1. 1
    Hand off to Orchestrator:
    @orchestrator execute .github/specs/todo-priority/tasks.json
  2. 2
    Watch the todo list update as each agent completes. Agents expected to run:
    Coder: Model → Migration → Input Model → Pages → UI badge/filter
    Tester: Unit tests → Integration tests
    Reviewer → Security → SRE → Document Writer
  3. 3
    If a rework loop triggers (e.g. security finding), do nothing — the orchestrator handles it automatically.
    You'll only be asked to intervene after 5 failed attempts.
✅Rework loops are automatic. You only get notified at human gates. This is the correct experience — observe, don't intervene.
Checks
✓
All tasks complete (status: "completed" in tasks.json)
✓
dotnet test passes — all existing + new tests green
✓
At least one rework loop observed (or pipeline ran clean — both are wins)
PHASE 5 PR Review — Gate 4 & Merge ⏱ 10 min ▼
🔒
Gate 4 — PR Approval (You)
Review the PR opened by the Orchestrator. Read all agent reports in the PR description. Your job is business logic review — the grunt work is already done.

Review checklist for the PR:

✓

✓

✓

✓
PR approved and merged ✓
