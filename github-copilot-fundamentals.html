01 / Introduction

Copilot is a development partner, not an automatic approval system.

GitHub Copilot helps you explore, explain, draft, transform, test, and review. The developer still supplies intent, context, judgment, and accountability.

Understand

Learn what Copilot can do, where it gets context, and how its responses are produced.

Interact

Choose the right interaction for the work: inline suggestions, chat, agentic tasks, CLI, or SDK.

Verify

Review generated output with tests, documentation, security checks, and domain expertise.

Learning objectives:by the end, you can choose the right Copilot surface, provide useful context, select a model for the task, and evaluate the result before it becomes part of the product.

02 / Concepts

The core ideas behind Copilot.

01

Prompt

Your request, question, code, or task description establishes intent.

02

Context

Relevant files, symbols, instructions, history, and tools shape the request.

03

Model

An LLM predicts a useful response from the information it receives.

04

Verification

You inspect, test, refine, and decide whether the result is fit for purpose.

Useful mental model:Copilot does not know your intent automatically. Better context reduces ambiguity; verification turns a plausible response into trusted work.

05 / Context and prompts

Good prompts are clear. Good context makes them useful.

State the task

  • Name the outcome and audience.
  • Identify the files, symbols, or behavior involved.
  • Describe constraints, conventions, and edge cases.

Shape the response

  • Ask for a plan before implementation when risk is high.
  • Request tests, alternatives, and assumptions.
  • Refine in small turns instead of writing one giant prompt.
Too broad

Add authentication.

More useful

Add role-based authentication to the existing API. Use the current middleware pattern, preserve anonymous health checks, cover invalid credentials, and add tests for each role.

Context is a design decision:include the information that changes the answer, while keeping sensitive or irrelevant material out of the conversation.

06 / Inline completions

Small suggestions can create large momentum.

Predict

Continue the code, comment, test, or configuration you have started.

Steer

Use names, comments, surrounding code, and small edits to guide the next suggestion.

Inspect

Accept, reject, or move through alternatives. A suggestion is a draft, not a decision.

Best fit:low-friction work where the surrounding code provides strong context, such as boilerplate, familiar patterns, and test scaffolding.

07 / Chat and modes

Use conversation when the work needs explanation, planning, or action.

Ask

Explain unfamiliar code, compare approaches, or answer a focused question.

Plan

Break a change into steps, surface assumptions, and agree on a direction before editing.

Act

Let an agent work across files and tools, with checkpoints and review at meaningful boundaries.

Choose the least powerful mode that fits the job:Ask for understanding. Plan before a risky change. Act when a scoped, multi-file task has clear acceptance criteria and review checkpoints.

08 / Copilot CLI

Bring Copilot into the terminal and the repository workflow.

$ copilot
# Explore a task in the repository
> Explain how this service handles retries
> Propose tests for the failure path
> Review the diff for unintended changes

Why it fits

Terminal-native work keeps repository navigation, version control, scripts, and Copilot close together.

Keep control

Inspect proposed commands and changes before execution, especially when tools can mutate the workspace.

10 / Responsible use

Trust is built through reviewable evidence.

Check the output

  • Run tests and inspect the diff.
  • Check security, privacy, licensing, and dependency implications.
  • Compare behavior with requirements and acceptance criteria.

Keep ownership visible

  • Understand the code you ship.
  • Record important assumptions and decisions.
  • Escalate uncertainty instead of hiding it behind fluent text.

Know the limits

  • Copilot does not guarantee correctness.
  • It does not automatically understand business intent.
  • It does not replace testing, review, or code ownership.
Responsible AI is a workflow:the quality bar belongs to the team, even when Copilot accelerates the work.
