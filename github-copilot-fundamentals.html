01 / Introduction

Copilot accelerates the work. You own the outcome.

The best results come from a simple partnership: you set the direction, Copilot expands the options, and you verify what ships.

1 / Direct

State the outcome, constraints, and evidence Copilot should use.

2 / Collaborate

Choose the surface that fits: completion, chat, agent, CLI, or SDK.

3 / Prove

Review the diff, run checks, and compare behavior with the requirement.

By the end:you can choose the right Copilot surface, provide useful context, select a model for the task, and evaluate the result before it becomes part of the product.

04 / AI Models

Choose the model for the job, not the hype.

Fast and economicalQuick answers for bounded, familiar work.Example: rename a variable or explain a small function.Speed
Balanced generalistThe everyday default for coding and conversation.Example: implement a feature or write its tests.Coverage
Deep reasoningMore deliberate analysis for ambiguity and trade-offs.Example: diagnose a complex failure or compare designs.Depth
Specialized capabilityOptimized for a specific language, task, or workflow.Example: use a domain-specific tool or mode.Fit
Selection rule:start with the least costly model likely to succeed. Move up when the task needs more reasoning, context, or reliability.

05 / Context and prompts

Prompt for the outcome. Curate the context.

Make intent explicit

  • Desired outcome and audience
  • Relevant files, symbols, or behavior
  • Constraints, conventions, and edge cases

Make proof explicit

  • Ask for a plan when risk is high
  • Request tests, assumptions, and trade-offs
  • Iterate in small, reviewable turns
Too broad

Add authentication.

More useful

Add role-based authentication to the existing API. Use the current middleware pattern, preserve anonymous health checks, cover invalid credentials, and add tests for each role.

Context is a design decision:include what changes the answer; exclude sensitive, stale, and irrelevant material.

06 / Inline completions

Inline completion is best for the next small step.

Start

Write the shape of the code, test, comment, or configuration you want.

Steer

Use names, comments, nearby patterns, and small edits to guide the next suggestion.

Decide

Accept, reject, or compare alternatives. Every suggestion is still a draft.

Best fit:repeatable work where the surrounding code already provides strong context: boilerplate, familiar patterns, and test scaffolding.

07 / Chat and modes

Match the mode to the level of agency you need.

Ask / Understand

Explain code, compare approaches, or answer one focused question.

Plan / Align

Break down the change, surface assumptions, and agree before editing.

Act / Execute

Delegate a scoped multi-file task with approvals and review checkpoints.

Agency rule:Ask for understanding. Plan before risk. Act only when scope, acceptance criteria, and review checkpoints are clear.

08 / Copilot CLI

Use the terminal when the workflow is already there.

$ copilot
# Explore a task in the repository
> Explain how this service handles retries
> Propose tests for the failure path
> Review the diff for unintended changes

Why it fits

Navigate, inspect, script, version, and ask questions without leaving the repository workflow.

Safety gate

Read proposed commands and diffs before execution, especially when tools can mutate the workspace.

09 / Copilot SDK

The SDK turns Copilot into a governed product capability.

Connect

Start a session and supply task-specific context.

Orchestrate

Combine prompts, tools, approvals, and application logic.

Govern

Define permissions, failure behavior, observability, and data handling.

SDK mindset:you are designing a product workflow, not adding a chat box. Make permissions, approvals, failure behavior, and data handling explicit.

10 / Responsible use

Do not ship confidence. Ship evidence.

Verify behavior

  • Run tests and inspect the diff
  • Check requirements and acceptance criteria
  • Test important edge cases

Review risk

  • Check security, privacy, licensing, and dependencies
  • Confirm data handling and permissions
  • Escalate uncertainty

Own the result

  • Understand the code you ship
  • Record assumptions and decisions
  • Keep human accountability visible
Quality bar:Copilot can accelerate production; only your workflow can establish whether the result is trustworthy.
