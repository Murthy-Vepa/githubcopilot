AI-Assisted Development

Move from typing code faster to thinking clearly with an AI collaborator.

IntentContextFlowEvidence
01 / Introduction

AI changes how software work gets done.

The developer still owns the problem, decisions, and quality. AI helps move from intent to evidence faster.

Start with outcomes

Define behavior, constraints, and what “good” looks like.

Work in loops

Ask, inspect, refine, test, and repeat.

Keep ownership

Review the result and make the engineering judgment.

The shift:intent + context + conversation + verification become part of the development process.
02 / Concepts

Good AI-assisted work is a loop, not a single prompt.

01

Intent

Name the problem, user, and outcome.

02

Context

Supply the code, constraints, and examples that matter.

03

Generation

Use AI to draft, compare, explain, or transform.

04

Evidence

Test, review, and observe the result.

Working rule:the quality of the loop matters more than prompt length or generation speed.
03 / Vibe Coding

Vibe coding is useful for exploration. It is not a quality strategy.

Move quickly from idea to draft, then add structure as the work becomes real.

ExploreTry the idea. Sketch the shape.
ShapeClarify behavior and constraints.
SpecifyMake requirements and acceptance criteria explicit.
ProveTest, review, observe, and document.
Boundary:exploration can be informal; production changes still need discipline and accountability.

04 / Prompt Engineering

Make your intent easy to act on.

Frame

Role. Outcome. Audience. Constraints. Relevant context.

Sequence

Plan first when uncertainty is meaningful.

Specify evidence

Ask for tests, assumptions, edge cases, and tradeoffs.

Prompt test:the response makes clear what changed, why it changed, and how to check it.

05 / Context Engineering

Context is a design decision.

Relevant codeStart with the owner, neighbors, interfaces, and tests.
ConstraintsState conventions, compatibility, security, and non-goals.
ExamplesShow a nearby pattern, input, output, or prior decision.
Noise controlExclude stale guidance, secrets, and conflicting sources.
Context rule:use the smallest context set that supports a useful, defensible decision.

06 / Workflow

Keep inspection close to generation.

Before generation

  • Clarify the behavior.
  • Locate the owner and tests.
  • Choose the mode and model.

After generation

  • Inspect the diff.
  • Run focused checks.
  • Refine using what you learned.
Workflow rule:use AI to compress feedback loops, not remove them.
07 / Collaboration modes

Match autonomy to risk.

AskExplain, compare, teach, investigate.
SuggestDraft an edit for a person to inspect.
PairExecute a bounded change with frequent review.
DelegateRun a defined workflow inside explicit boundaries.
Risk rule:as consequence increases, approvals, ownership, and evidence must become clearer.
08 / Verification

Generated code is a draft until evidence says otherwise.

Read

Diff. Control flow. Dependencies. Errors. Data boundaries.

Run

Start focused; expand to build, integration, or runtime checks.

Review

Does it solve the real problem and fit the repository?

Verification is part of prompting:ask for tests and assumptions before the code exists.
09 / From exploration to specification

When the work matters, turn conversation into a specification.

DiscoverExplore users, constraints, and possible approaches.
SpecifyRecord behavior, scenarios, and acceptance criteria.
PlanBreak the work into owned tasks and quality gates.
ImplementBuild inside the agreed boundaries; validate against the spec.
Complementary strengths:AI helps find the path; specifications help the team travel it consistently.

10 / Team practices

Make AI-assisted work legible.

Share patterns

Keep useful prompts, examples, and decisions with the project.

Review outcomes

Apply the same technical and security bar as any change.

Improve the system

Turn repeated work into better context or automation.

Team maturity test:people can explain how AI was used, what was checked, and what should improve next.
11 / Responsible use

Keep human judgment where consequences begin.

Protect

  • No secrets or unnecessary sensitive data.
  • Respect licensing, privacy, security, and access.
  • Use least privilege.

Account

  • Verify before shipping.
  • Record assumptions and decisions.
  • Escalate uncertain or high-impact outcomes.
Safety is practical engineering:clear boundaries and evidence make AI assistance safer and easier to improve.
