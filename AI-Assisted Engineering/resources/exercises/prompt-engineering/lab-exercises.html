EX 01 Write copilot-instructions.md ⏱ 20 min ▼
Goal
Create a global instructions file that permanently teaches Copilot your team's conventions — so every chat gets the right context automatically.
  1. 1
    Create (or open) .github/copilot-instructions.md in the repo root and fill in these sections:
    ## Tech Stack
    - .NET 10, Razor Pages, EF Core, SQL Server LocalDB
    - xUnit with FluentAssertions, Moq for mocking

    ## Architecture Conventions
    - Repository pattern: `IRepository<T>` in Repositories/
    - No raw SQL — EF Core LINQ only
    - Always use nullable reference types (#nullable enable)

    ## Logging
    - Use ILogger<T> — never Console.Write
    - Structured log templates, not string interpolation

    ## Security
    - Never log PII or connection strings
    - Validate user input at the page model boundary
  2. 2
    Open a fresh chat (Ctrl+Shift+N for new thread) and ask:
    @workspace add a GetByPriorityAsync method to the TodoRepository
  3. 3
    Check the response: Does it use ILogger? Does it use EF Core LINQ? Does it have async/await?
  4. 4
    If not — refine your instructions and try again. Iteration is expected.
Validation Checklist
✓
Instructions file created with at least 5 rules
✓
Generated code uses ILogger (not Console.Write)
✓
Generated code follows the repository pattern
✓
Generated code uses async/await correctly
EX 02 Scoped .instructions.md Files ⏱ 15 min ▼
Goal
Create folder-specific instructions that apply different rules to different layers of the application using applyTo patterns.
Create src/TodoApp/Data/.instructions.md
---
applyTo: '**/*.cs'
---
## Data Layer Rules
- Always use parameterised queries or EF Core LINQ
- Never call SaveChangesAsync inside a loop
- Use AsNoTracking() for all read-only queries
- Never access DbContext outside this folder
Create src/TodoApp/Pages/.instructions.md
---
applyTo: '**/*.cs'
---
## Pages Rules
- Always check ModelState.IsValid before processing
- Return Page() when validation fails (not RedirectToPage)
- Use TempData for success messages after redirects
- Never inject repositories directly — services only
Test the scoped instructions
// Open TodoRepository.cs → ask Copilot to add a search method
@workspace add a SearchByTitleAsync method to TodoRepository

// Open Index.cshtml.cs → ask Copilot to add a filter feature
@workspace add a filter by completion status to the Index page handler
Validation Checklist
✓
Data layer .instructions.md created with correct frontmatter
✓
Pages .instructions.md created with correct frontmatter
✓
Data layer generated code uses AsNoTracking on read queries
✓
Pages generated code checks ModelState.IsValid
EX 03 Build a Prompt Template ⏱ 20 min ▼
Goal
Create a reusable .prompt.md template with variables that your team can run via the Command Palette for a task you repeat often.
  1. 1
    Create the prompts folder if it doesn't exist: .github/prompts/
  2. 2
    Create .github/prompts/add-field.prompt.md:
    ---
    description: Add a new field to an existing entity with all layers updated
    mode: agent
    variables:
      - name: EntityName
        description: The entity to modify (e.g. TodoItem)
      - name: FieldName
        description: New field name in PascalCase (e.g. Priority)
      - name: FieldType
        description: C# type (e.g. string?, int, DateTime?)
    ---
    Add field `${{FieldName}}` of type `${{FieldType}}` to `${{EntityName}}`.
    Update: model, input model, Razor Pages, and EF Core migration.
    Follow .github/copilot-instructions.md conventions.
  3. 3
    Run it: Ctrl+Shift+P → Chat: Run Prompt → select the template.
  4. 4
    Enter variables: EntityName=TodoItem, FieldName=Priority, FieldType=string?
Validation Checklist
✓
Template created with correct frontmatter (description, mode, variables)
✓
Template appears in Command Palette under "Chat: Run Prompt"
✓
Template runs with variables and follows team conventions
EX 04 Write a SKILL.md Package ⏱ 20 min ▼
Goal
Create a SKILL.md that encapsulates the EF Core migration procedure as an on-demand domain knowledge package Copilot loads only when needed.
  1. 1
    Create the folder: .github/skills/ef-migration/
  2. 2
    Create .github/skills/ef-migration/SKILL.md with this structure:
    ---
    name: ef-migration
    description: |
      Run EF Core database migrations for the TodoApp project.
      WHEN: "run migration", "add migration", "update database",
      "ef core migration", "schema change", "dotnet ef".
      DO NOT USE FOR: seeding data, dropping the database.
    ---
    ## Steps
    1. Add migration: `dotnet ef migrations add Name ...`
    2. Review Up() and Down() methods
    3. Apply: `dotnet ef database update ...`
    4. Verify app starts correctly
  3. 3
    Reload VS Code window (Ctrl+Shift+P → Reload Window)
  4. 4
    Ask in chat: how do I add a migration after adding a Priority field?
    Verify the skill loads and provides the specific project paths and commands.
🎯Reference the full skill-template.md for the complete SKILL.md authoring guide with WHEN/DO NOT USE FOR patterns.
Validation Checklist
✓
SKILL.md created at correct path (.github/skills/ef-migration/SKILL.md)
✓
Description has WHEN and DO NOT USE FOR clauses
✓
Skill loads when you ask a migration-related question
✓
Steps are accurate for this specific project
EX 05 Evaluate Prompt Quality ⏱ 15 min ▼
Goal
Turn prompt quality into observable criteria instead of relying on whether the first response feels useful.
  1. 1
    Choose a task such as adding an API endpoint or generating tests.
  2. 2
    Write a one-sentence prompt, then a Role → Context → Task → Constraints → Format version.
  3. 3
    Run both prompts in a fresh chat and score each response from 1–5 for correctness, completeness, convention fit, and testability.
  4. 4
    Revise the stronger prompt once based on the lowest score and record what changed.
Validation Checklist
✓
Two prompt versions were tested in fresh chats
✓
Scores include evidence, not just a preference
✓
A revised prompt and rationale were saved
EX 06 Govern a Team Prompt ⏱ 15 min ▼
Goal
Make a reusable prompt safe and maintainable for other developers to run in the repository.
  1. 1
    Choose the prompt template from Exercise 3 and add explicit input variables and defaults.
  2. 2
    Add guardrails for secrets, PII, destructive commands, scope of files, and required verification.
  3. 3
    Ask a partner to run it with incomplete and malicious-looking inputs, then refine the failure guidance.
  4. 4
    Add a short README section describing purpose, inputs, expected output, and an example invocation.
Validation Checklist
✓
Variables and defaults are documented
✓
Safety and scope guardrails reject unsafe inputs
✓
README example runs successfully
⭐ Bonus — Prompt Chaining
Chain multiple prompts in a single agent session:

@workspace First: run the add-field prompt for DueDate (DateTime?) on TodoItem. Then: generate tests for the new field using the generate-tests prompt for TodoService.

Does Copilot handle both sequentially? What's the quality of the output?
