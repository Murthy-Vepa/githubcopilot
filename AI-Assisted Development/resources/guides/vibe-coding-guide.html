Orientation

AI-Assisted Development changes where your effort goes. You spend less time typing every line and more time expressing intent, reviewing evidence, and steering the next iteration.

The operating principle: You bring the product idea and the judgment. Copilot helps translate the idea into artifacts, code, and alternatives. You remain responsible for deciding what is correct, secure, accessible, and worth keeping.
Describe

State the desired experience, constraints, examples, and success conditions in natural language.

Inspect

Read the generated requirements, diagrams, code, and tests as proposed work, not as truth.

Refine

Use feedback, tests, and concrete corrections to move from an exciting first draft toward a dependable result.

02

What is AI-assisted development?

The phrase describes a shift from line-by-line implementation toward product intent expressed through conversation with an AI coding tool.

Where it helps

Rapid prototypes, proof-of-concepts, feature exploration, refactoring, documentation, automation, and technology experiments.

Who can use it

Developers, product and business professionals, educators, engineers, and data scientists can use natural language to explore an idea.

What it changes

The developer's role expands from writing code to shaping intent, checking output, testing behavior, and making trade-offs visible.

What it does not change

Security, architecture, performance, maintainability, accessibility, and production accountability still require human judgment.

Risk boundary: AI-generated code may contain technical debt, weak error handling, security vulnerabilities, poor modularity, or missing tests. AI-Assisted Development accelerates decisions; it does not make decisions for you.
03

The AI-assisted development process

Microsoft Learn frames the process as three overlapping phases. The overlap is useful: planning can continue while the prototype teaches you what the product actually needs.

1. EnvisionClarify the problem, users, value, scope, platform, data, and risks.
2. PlanCreate a PRD, user flows, wireframes, and quality guidelines.
3. PrototypeAsk Agent to turn the intent into a working first version.
4. IterateAdd features, improve UI, connect data, test, refactor, and optimize.
5. ReassessKeep the idea, change the scope, or move to a more formal spec.

The five-step feedback loop

  1. Prompt: describe the outcome, context, constraints, and examples.
  2. Suggestion: let Copilot propose code, files, tests, or a design.
  3. Review: compare the result with requirements, conventions, and risks.
  4. Refine: correct the prompt or the implementation with specific feedback.
  5. Repeat: keep the loop small enough that every change remains understandable.
Protect flow without losing rigor: work in focused blocks, keep changes incremental, and validate each meaningful step. Momentum comes from short feedback cycles, not from accepting everything quickly.
04

Effective prompts

A prompt is a natural-language instruction, question, or task description. The best prompts give Copilot enough signal to produce a result you can evaluate.

Start general, then get specific

State the goal first. Add behavior, constraints, edge cases, and implementation context after the goal is clear.

Provide concrete examples

Show sample inputs, expected outputs, user flows, error messages, or visual references.

Break down complex work

Split a large feature into smaller prompts that can be reviewed and tested independently.

Eliminate ambiguity

Name the file, function, component, bug, library, or behavior. Replace “fix this” with a verifiable request.

Attach relevant context

Open or attach the relevant files and symbols. Use references such as #file and #selection.

Iterate deliberately

Start a focused thread, refine with concrete feedback, and discard irrelevant conversation history.

Prompt pattern

Goal: Add CSV export to the existing report page. Context: Use the current table component and the existing download helper. Keep the export client-side. Requirements: - Include the visible columns in their displayed order. - Escape commas, quotes, and line breaks correctly. - Preserve the current loading and error states. - Add unit tests for empty data and quoted values. Before editing, list the files you expect to change and any assumptions.

Decide what to do with a suggestion

ActionUse it when
AcceptIt meets the requirements, follows local patterns, handles errors, and has an appropriate test story.
RejectIt solves a different problem, introduces security risk, uses deprecated APIs, or adds needless complexity.
ModifyThe core idea is sound but needs a narrower scope, better names, additional validation, or a project-specific pattern.
05

Requirements and coding guidelines

Planning is not opposed to AI-assisted development. It gives the conversation a shared direction and reduces rework.

Product vision

Problem, target audience, value, platform, MVP scope, technology, data, and security considerations.

PRD

Summary, audience, features, UI, navigation, sample data, technical requirements, use cases, and out-of-scope items.

Wireframes

Low-, medium-, or high-fidelity views that make layout, navigation, and user flow visible before implementation.

MVP feature sorting

Must-have

Without it, the product cannot demonstrate its core value.

Should-have

Important for usability, but not required for the first useful version.

Could-have

Valuable later, but a candidate for a future iteration.

Guidelines worth making explicit

  • Code style: naming, formatting, documentation, and project patterns.
  • Security: input validation, authentication, authorization, secrets, and data protection.
  • Testing: unit, integration, accessibility, and user acceptance expectations.
  • Performance: response times, load behavior, and resource boundaries.
  • Accessibility: keyboard access, semantic structure, contrast, and inclusive interaction.
Suggest coding standards for a secure, accessible web app built with [framework]. Include formatting, testing, performance, accessibility, and security guidelines. Prefer the patterns already present in this repository. Return the result as a concise project instruction file.

Customize Copilot

Move stable context out of individual prompts and into reusable project configuration.

MechanismBest useKey idea
.github/copilot-instructions.mdWorkspace-wide conventionsOne shared file automatically included in relevant requests across editors.
*.instructions.mdTargeted guidanceUse applyTo patterns for language, framework, or file-specific rules.
Prompt filesRepeatable tasksReusable requests for PRDs, scaffolding, reviews, tests, or plans.
Settings instructionsScenario-specific behaviorConfigure code generation, testing, review, commits, and pull request descriptions.
Custom chat modesWorkflow boundariesSeparate planning, research, implementation, and review with different tool access.
Avoid conflicting rules: keep instructions concise, organize them by topic, store shared guidance in version control, and target rules with file patterns where possible.

Starter instruction file

--- applyTo: "**" --- # Project standards - Preserve existing architecture and public APIs unless the task requires a change. - Add or update tests for changed behavior. - Validate user input and never expose secrets in source or logs. - Follow the repository's naming, formatting, and error-handling patterns. - Explain assumptions before making cross-cutting changes.

The Agent exercise

The Microsoft Learn exercise applies the complete method to a prototype e-commerce app: define requirements, create a prototype, and refine its design and functionality.

Prepare

Have an active GitHub account, Visual Studio Code, and access to GitHub Copilot. The exercise links to a public GitHub instruction page.

Define

Describe the product experience, audience, core features, navigation, sample data, styling, and constraints.

Build

Use Agent to turn requirements and wireframe direction into a working prototype with basic functionality and navigation.

Refine

Iterate on visual design, behavior, data integration, tests, quality, and edge cases. Return to the requirements when scope drifts.

Practice rule: ask Agent to explain the files it changed, review the diff, run the app, test the primary user flow, and make one focused improvement at a time.

Assessment checklist

Use these prompts to test whether you can explain the module, not just recognize its vocabulary.

  • Can you explain how AI-assisted development differs from line-by-line coding?
  • Can you name the three phases: envision and plan, initial prototype, and iterative feature development?
  • Can you describe the Prompt, Suggestion, Review, Refine, Repeat feedback loop?
  • Can you improve a vague prompt by adding context, examples, constraints, and expected behavior?
  • Can you explain why a PRD and wireframe help both people and AI?
  • Can you distinguish custom instructions, prompt files, settings instructions, and chat modes?
  • Can you identify a case where AI output should be rejected rather than accepted?
  • Can you describe why production code still needs experienced review?

A practical playbook

Keep this sequence beside your next prototype session.

  1. Frame the idea: write the problem, audience, value, and non-goals in plain language.
  2. Ask Copilot to question it: request missing assumptions, edge cases, risks, and a short product vision.
  3. Shape the MVP: sort features into must-have, should-have, and could-have.
  4. Visualize the experience: describe the primary user flow and generate a low-fidelity wireframe.
  5. Set the rules: define security, accessibility, testing, performance, and code-style expectations.
  6. Build the smallest prototype: ask Agent to implement the core flow and explain the file changes.
  7. Run the loop: prompt, inspect, review, refine, test, and repeat.
  8. Choose the next mode: continue exploring, or capture the validated behavior in a specification.
10

From vibe to spec

AI-Assisted Development and spec-driven development are complementary. The prototype helps discover what matters; the specification makes the discovered behavior durable and traceable.

Capture

Ask Copilot to extract the user-visible behaviors the prototype now supports.

Clarify

Convert assumptions and edge cases into explicit requirements, non-goals, and open questions.

Trace

Assign requirement IDs, acceptance criteria, implementation tasks, and tests.

Review the current prototype and extract its functional requirements. For each requirement: - Assign a sequential REQ-ID. - Write Given/When/Then acceptance criteria. - Identify the relevant screen, API, component, or service. - List edge cases and security considerations. - Separate observed behavior from assumptions. Then list non-goals and open questions. Do not change code.
Decision point: stay in vibe mode while the product is changing rapidly. Move toward a specification when the behavior matters to other people, production reliability, security, compliance, or a long maintenance horizon.
