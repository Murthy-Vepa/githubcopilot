Agents

Six guided exercises covering agent mode, autonomous implementation, MCP tools, verification loops, permission-aware planning, and multi-agent handoffs.

⏱ ~80 min total
🧪 6 Exercises
🟡 Intermediate
🧭 Before You Begin

Use a small, disposable project or a safe branch. Do not place secrets, personal data, or production credentials in prompts, files, or MCP configuration.

Agents can inspect, edit, execute, and call external tools. Review the plan, permissions, diffs, tool inputs, and test evidence before accepting a result.

EX 01
Enable & Explore Agent Mode
⏱ 15 min
▼
🎯 Goal
Switch Copilot Chat to agent mode and observe how it plans and uses tools differently from standard chat.
  1. 1
    Switch to Agent Mode
    In VS Code, open Copilot Chat (Ctrl+Alt+I). Click the mode selector dropdown at the top of the chat panel and switch from "Ask" or "Edit" to Agent.
  2. 2
    Submit a multi-step task
    Try: "Find all TODO comments in the workspace, create a markdown file called todos.md listing them with file names and line numbers, then open the file."
  3. 3
    Observe the planning step
    Before executing, Copilot will display a plan with numbered steps. Read it carefully — notice how it identifies which tools it needs (search, file write, etc.).
  4. 4
    Approve and watch execution
    Click "Run" or approve each step. Watch Copilot use the file search and create tools sequentially. Review the generated todos.md.
  5. 5
    Compare with chat mode
    Switch back to Ask mode and give the same instruction. Notice the difference — Ask mode suggests the code; Agent mode *does the work*.
Tip: Agent mode respects your workspace guardrails. It will ask for confirmation before overwriting files or running terminal commands by default.
Validation Checklist
✓
Created todos.md with correct file and line references
✓
Observed and explained the agent planning step
✓
Explained the difference between Ask and Agent mode
EX 02
Autonomous Refactoring Task
⏱ 20 min
▼
🎯 Goal
Give the agent a real refactoring task spanning multiple files, with verification via terminal commands.
  1. 1
    Pick a code file with potential improvements
    Choose any TypeScript, JavaScript, Python, or C# file in a personal project. Alternatively, create a sample file with a few functions that have magic numbers, missing error handling, or inconsistent naming.
  2. 2
    Give the agent an outcome-oriented prompt
    Try: "Refactor [filename]: extract all magic numbers to named constants, add JSDoc comments to all exported functions, and ensure all async functions have try/catch. Don't change any logic. Run the linter after and fix any warnings."
  3. 3
    Review the plan before approving
    Check the agent's plan. If any step looks risky (e.g., deleting lines you want to keep), tell the agent to adjust before proceeding.
  4. 4
    Approve step-by-step
    Approve each sub-step individually. Watch the diff view for each file change to confirm the agent is respecting your "don't change logic" constraint.
  5. 5
    Review final state
    Verify the linter output shows zero warnings. Check that at least 3 magic numbers were extracted and 2+ functions have JSDoc comments.
Safety: Always review agent-generated changes before committing. Agent mode can modify multiple files — use git diff or VS Code's diff view to verify each change.
Validation Checklist
✓
Magic numbers were extracted to named constants
✓
Exported functions received useful documentation
✓
Lint passes and the diff preserves logic
EX 03
Wire Up Your First MCP Server
⏱ 25 min
▼
🎯 Goal
Configure an MCP server in VS Code and use it as a tool inside agent mode. You'll use the GitHub MCP server to query issues directly from Copilot.
  1. 1
    Create .vscode/mcp.json
    In your workspace root, create .vscode/mcp.json with the GitHub MCP server config:
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "${env:GITHUB_TOKEN}"
      }
    }
  }
}
  1. 2
    Set your GitHub token
    In your terminal, run: $env:GITHUB_TOKEN = "ghp_your_token_here". Use a token with repo read scope. Never hardcode tokens in mcp.json.
  2. 3
    Verify the MCP server loads
    Open Copilot Chat in Agent mode. You should see the GitHub MCP tools available in the tool selector. Look for tools like list_issues, get_file_contents.
  3. 4
    Use MCP via agent mode
    Try: "Using the GitHub MCP server, list the 5 most recent open issues in microsoft/vscode. Create a markdown summary file issues-summary.md with issue title, number, and URL."
  4. 5
    Inspect the tool calls
    Expand the agent's execution log. You should see it calling MCP tools. Note the tool name, inputs, and outputs for each call.
Tip: MCP servers run locally on your machine — data never leaves your environment unless the MCP server itself makes external calls (like the GitHub server calling GitHub's API).
Validation Checklist
✓
MCP tools loaded and the token stayed outside mcp.json
✓
Created issues-summary.md with five issues
✓
Inspected tool names, inputs, and outputs in the log
EX 04
Build & Test a Mini Feature End-to-End
⏱ 20 min
▼
🎯 Goal
Use agent mode to complete a full mini-feature cycle: write code, write tests, run tests, fix failures — all autonomously.
  1. 1
    Set up a simple project (if needed)
    If you don't have a project handy, ask the agent: "Create a new Node.js project with a utils.js file containing a formatCurrency(amount, currency) function. No external dependencies."
  2. 2
    Give a complete outcome prompt
    Try: "For the formatCurrency function in utils.js: 1) Add input validation with descriptive error messages. 2) Write unit tests in utils.test.js covering happy path, negative amounts, zero, and invalid inputs. 3) Run the tests. 4) Fix any failures. Report final test results."
  3. 3
    Observe the full loop
    Watch the agent write code, create the test file, run tests via terminal, observe failures, fix the code or tests, and re-run — all without you intervening.
  4. 4
    Review the final output
    Check: are the tests meaningful (not just checking that the function exists)? Does validation cover edge cases? Did the agent self-correct when tests failed?
Tip: The "run tests and fix failures" instruction is the key pattern — it transforms the agent from a code writer into a self-verifying developer. Use it whenever writing testable code.
Validation Checklist
✓
Tests cover happy path, negative, zero, and invalid inputs
✓
All tests pass after at least one agent correction
✓
Validation errors are meaningful and reviewable
EX 05
Plan the Agent Safely
⏱ 15 min
▼
🎯 Goal
Review an agent plan for scope, permissions, data exposure, and rollback before allowing execution.
  1. 1
    Give the agent a bounded task
    Ask it to update one feature and its tests, naming the allowed folders and the commands it may run.
  2. 2
    Inspect the proposed plan
    Mark each step as read, write, execute, or external-network access. Reject anything outside the task boundary.
  3. 3
    Define a stop condition
    Require the agent to pause on destructive commands, secrets, failing tests, or unexpected files.
Validation Checklist
✓
Categorized every plan step by permission and risk
✓
Rejected work outside the stated task boundary
✓
Documented stop conditions and a rollback action
EX 06
Multi-Agent Handoff
⏱ 20 min
▼
🎯 Goal
Split one feature between planning, coding, testing, and review agents with a clear handoff packet.
  1. 1
    Create the handoff
    Write the goal, constraints, files in scope, acceptance criteria, test command, and known risks in a short markdown file.
  2. 2
    Run the roles in order
    Have one agent implement, a second test, and a third review the diff against the handoff packet.
  3. 3
    Resolve one finding
    Route a review finding back to the coding agent and record the evidence that the fix was verified.
Validation Checklist
✓
Each agent received a focused handoff packet
✓
Tests ran after implementation and results were recorded
✓
A review finding and verification evidence are recorded
