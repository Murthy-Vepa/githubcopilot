# MetLife Investments Management – Copilot Instructions

## Tech Stack
- .NET 10, C# 13 (nullable reference types, primary constructors)
- ASP.NET Core Web API (src/Investments.Api)
- Blazor Server (src/Investments.Web)
- Entity Framework Core 9 + SQL Server 2022 (src/Investments.DataAccess)
- xUnit + Moq + FluentAssertions (tests)
- Azure DevOps CI/CD; Azure App Services, Functions, Service Bus

## Architecture Boundaries
- Business logic ONLY in src/Investments.Services/
- HTTP concerns ONLY in src/Investments.Api/Controllers/
- Data access ONLY via repository interfaces in src/Investments.DataAccess/
  — never inject DbContext directly into a controller or service
- Blazor UI ONLY in src/Investments.Web/
- EF Core migrations in db/Migrations/ — never edit deployed migrations

## C# Naming Conventions
- PascalCase for files, classes, methods, properties (PortfolioService.cs)
- Interface prefix I (IPortfolioService, ITradeRepository)
- Private fields _camelCase (_portfolioRepository, _logger)
- Async methods suffix Async (GetPortfolioAsync, ExecuteTradeAsync)
- Test class suffix Tests; test name MethodName_Condition_ExpectedOutcome

## Verification — Run Before Declaring Complete
1. dotnet test                          # all tests pass
2. dotnet build -warnaserror            # zero warnings
3. dotnet format --verify-no-changes    # code style clean

## Domain Context
- MetLife Investments Management — Portfolio, Fund, Trade, Asset, Holdings
- financial calculations: decimal ONLY — NEVER double or float
- soft-delete only for Portfolio and Trade records (set DeletedAt, never dbContext.Remove())
- all financial writes call _auditService.RecordAsync(entity, entityId, action, actorId)

## Security — Non-Negotiable
- NEVER log PII: account numbers, SSN, tax IDs, portfolio values tied to an individual
- parameterized SQL / EF Core ONLY — never string-concatenated queries
- [Authorize] on all controllers touching investment or client data
- validate all request DTOs with FluentValidation before processing
- secrets in Azure Key Vault — never in appsettings.json or source code

## Special Projects
- portfolio-analytics: Azure Databricks / Python / PySpark — Python rules apply, not C# rules
- Legacy Java integration service: read-only — no new features added there
The decimal rule appears in Domain Context where engineers associate it with financial domain — not in a generic "coding standards" section they might skim.
Verification lists exact commands. Copilot can quote-run them; generic "run tests" does not tell an agent which runner to use.
Special Projects section prevents Copilot from applying C# conventions to the Databricks PySpark codebase.
Common pitfall
Adding the decimal rule in a comment block that Copilot ignores vs. putting it in a dedicated bullet. Test by asking Copilot to add a NAV calculation — if it uses double, the rule isn't prominent enough.

# Blazor Component Conventions – MetLife Investments

## Component Structure
- Use @code { } block for component logic
- Inject services: @inject IPortfolioService PortfolioService
- Load async data in OnInitializedAsync — never in constructor
- Handle three states: loading (bool isLoading), error (string? errorMessage), data

## State Management
- Page-level state: component properties in @code block
- Shared cross-component state: scoped DI services in src/Investments.Web/State/
- Never use static fields or singletons for UI state

## API Calls
- All HTTP calls via typed HttpClient wrappers in src/Investments.Web/Services/
- Always wrap in try/catch; set errorMessage on exception
- Use CancellationToken from component lifecycle where possible

## Typical Pattern
```razor
@inject IPortfolioService PortfolioService

@if (isLoading) { <p>Loading...</p> }
else if (errorMessage is not null) { <p class="error">@errorMessage</p> }
else { <!-- render data --> }

@code {
    private bool isLoading = true;
    private string? errorMessage;
    private Portfolio? portfolio;

    protected override async Task OnInitializedAsync()
    {
        try { portfolio = await PortfolioService.GetAsync(Id); }
        catch (Exception ex) { errorMessage = ex.Message; }
        finally { isLoading = false; }
    }
}
```
The example pattern is the most important element. Copilot generates conformant code when it has a concrete before/after template in the instruction file.
applyTo scoped to .razor only means these conventions don't leak into API or service classes. Narrowest scope wins.

# ASP.NET Core API Security Conventions – MetLife Investments

## Input Validation (MANDATORY)
- Inject IValidator<TRequest> for every action with a request body
- Call await validator.ValidateAndThrowAsync(request) before any business logic
- Invalid requests: HTTP 400 with RFC 7807 ProblemDetails — never continue processing

## Authentication & Authorization (MANDATORY)
- [Authorize] on every controller accessing investment or client data
- Write operations: [Authorize(Policy = "PortfolioManager")] or [Authorize(Policy = "TradeExecutor")]
- Fund admin: [Authorize(Policy = "FundAdministrator")]
- Never rely on caller assumptions — always verify

## Data Access
- Inject IPortfolioRepository, ITradeRepository, IFundRepository (interfaces from src/Investments.DataAccess)
- NEVER inject DbContext directly into a controller
- NEVER write inline LINQ in action methods — call repository methods

## Error Responses
- Use global exception middleware (Investments.Api/Middleware/ExceptionMiddleware.cs)
- Return ProblemDetails with correlationId property
- NEVER include stack traces, SQL messages, or exception details in responses

## Example Controller Pattern
```csharp
[ApiController]
[Route("api/[controller]")]
[Authorize]
public class PortfoliosController : ControllerBase
{
    private readonly IPortfolioRepository _repository;
    private readonly IValidator<CreatePortfolioRequest> _validator;

    public PortfoliosController(
        IPortfolioRepository repository,
        IValidator<CreatePortfolioRequest> validator) 
        => (_repository, _validator) = (repository, validator);

    [HttpPost]
    [Authorize(Policy = "PortfolioManager")]
    [ProducesResponseType<PortfolioDto>(StatusCodes.Status201Created)]
    [ProducesResponseType(StatusCodes.Status400BadRequest)]
    [ProducesResponseType(StatusCodes.Status401Unauthorized)]
    public async Task<IActionResult> CreateAsync(CreatePortfolioRequest request)
    {
        await _validator.ValidateAndThrowAsync(request);
        var portfolio = await _repository.CreateAsync(request);
        return CreatedAtAction(nameof(GetAsync), new { id = portfolio.Id }, portfolio);
    }
}
```

## Framework Requirements
- xUnit ONLY — no MSTest, no NUnit
- Moq for all mocks (Mock<T> as private readonly fields)
- FluentAssertions for assertions (.Should().Be(), .Should().ThrowAsync<T>())

## Setup Conventions
- Constructor injection for System Under Test (SUT)
- Mock<T> fields declared as: private readonly Mock<IFoo> _fooMock = new();
- Create SUT in constructor: _sut = new ServiceClass(_fooMock.Object);
- Do NOT share mock state between tests (no [TestInitialize])

## AAA Structure
// Arrange  — setup inputs and mock returns
// Act      — single call to the method under test
// Assert   — verify result and mock interactions

## Test Name Format: MethodName_Condition_ExpectedOutcome
Example: GetPortfolioAsync_PortfolioNotFound_ThrowsPortfolioNotFoundException

## Coverage Per Public Method
- At least 1 happy path (expected success)
- At least 1 error path: _mock.Setup(...).ThrowsAsync(new SomeException())
- At least 1 boundary test: null/empty parameters

## Async Rules
- Test methods return async Task
- Use await Assert.ThrowsAsync<T>(() => _sut.MethodAsync())
- NEVER use .Result or .Wait()

## Post-Generation
Run: dotnet test --filter "FullyQualifiedName~[ClassName]Tests" --no-build
Report any compile errors or test failures.
SAMPLE OUTPUT: PortfolioServiceTests.cs (extract) 
public class PortfolioServiceTests
{
    private readonly Mock<IPortfolioRepository> _repoMock = new();
    private readonly Mock<IAuditService> _auditMock = new();
    private readonly PortfolioService _sut;

    public PortfolioServiceTests()
        => _sut = new PortfolioService(_repoMock.Object, _auditMock.Object);

    [Fact]
    public async Task GetPortfolioAsync_ValidId_ReturnsPortfolio()
    {
        // Arrange
        var expected = new Portfolio { Id = 1, Name = "Growth Fund" };
        _repoMock.Setup(r => r.GetByIdAsync(1)).ReturnsAsync(expected);

        // Act
        var result = await _sut.GetPortfolioAsync(1);

        // Assert
        result.Should().BeEquivalentTo(expected);
    }

    [Fact]
    public async Task GetPortfolioAsync_PortfolioNotFound_ThrowsNotFoundException()
    {
        // Arrange
        _repoMock.Setup(r => r.GetByIdAsync(99)).ReturnsAsync((Portfolio?)null);

        // Act & Assert
        await Assert.ThrowsAsync<PortfolioNotFoundException>(
            () => _sut.GetPortfolioAsync(99));
    }
}

P-05EF Core Query Performance Review Prompt✔ Solution▼
Performance review prompt detecting N+1, missing AsNoTracking(), unbounded results, and sync-over-async — with corrected code snippets per finding.
FILE: .github/prompts/ef-performance-review.prompt.md 
---
mode: ask
---

Review the attached EF Core repository/service code for performance anti-patterns.

## Anti-Patterns to Detect

### N+1 Queries
Navigation property accessed in a loop without .Include() on the original query.
Fix: add .Include(p => p.Holdings) to the LINQ query.

### Missing AsNoTracking()
Read-only queries (no SaveChanges after) missing .AsNoTracking().
Fix: add .AsNoTracking() to all read-only queries.
WARN: Do NOT add AsNoTracking() if the entity will be updated via SaveChanges.

### Unbounded Result Sets
.ToListAsync() / .ToArrayAsync() without .Take(n).
Fix: add .Take(maxResults) and add pagination parameters.

### Sync-over-Async
.Result or .Wait() on a Task. Causes deadlock risk in ASP.NET Core.
Fix: use await consistently throughout the call chain.

### Missing FK Indexes
WHERE clause on a column without HasIndex() in model config.
Fix: add migration with CreateIndex() on the FK column.

## Output Format
| # | File:Line | Anti-Pattern | Estimated Impact | Fix |
|---|-----------|-------------|-----------------|-----|

For each finding, include a corrected code snippet.

# Security Reviewer Agent — MetLife Investments

## Role
Senior application security engineer. OWASP Top 10, ASP.NET Core security,
financial services compliance (SOX, FINRA, GDPR). Read-only — you never modify code.

## Method
1. Read .github/copilot-instructions.md and .github/instructions/api.instructions.md
2. Run list_directory on src/ to identify changed files
3. For each changed C# file, check:
   - [Authorize] on controllers with financial data
   - FluentValidation before business logic
   - No PII in _logger.* calls (AccountNumber, TaxId, SSN, DOB)
   - No raw SQL string concatenation
   - ProblemDetails for all error responses
   - Soft-delete pattern (no dbContext.Remove() on Portfolio/Trade)
4. For CRITICAL findings: stop and say
   "CRITICAL FINDING in [file]: [description]. Please review before I continue."
   Wait for explicit confirmation.
5. Generate report

## Report Format
**Security Review Report**
Date: [date] | Scope: [files reviewed]

| # | Severity | Category | File:Line | Finding | Remediation |
|---|----------|----------|-----------|---------|-------------|

**Overall Risk:** LOW / MEDIUM / HIGH / CRITICAL
**Required Before Merge:** [list or "None"]
Common pitfall
Adding create_file or edit_file "to help the developer fix issues" undermines the agent's value. A fix-and-ship agent removes the human review step. Read-only + structured report is the correct model for regulated financial code.

# Test Coverage Gap Finder — MetLife Investments

## Role
QA engineer expert in xUnit, Moq, FluentAssertions, and financial C# behavioral testing.

## Method
1. Read the source file: list all public methods and identify branches
   (if/else, try/catch, null checks, enum switches)
2. Read the test file (if exists): identify which branches have tests
3. Build gap matrix: Method | Branch | Covered (Yes/No)
4. Classify gaps:
   - Critical: exception handling, domain invariant violations (decimal check, soft-delete)
   - High: null/empty boundary, async failure paths
   - Normal: alternate happy paths
5. Select top 3 gaps by risk
6. Generate xUnit tests for top 3 using:
   - Mock<T> fields, constructor injection
   - AAA pattern (// Arrange // Act // Assert)
   - MethodName_Condition_ExpectedOutcome naming
7. Run: dotnet test --filter "FullyQualifiedName~[ClassName]Tests" --no-build
8. Report gap matrix + generated tests + estimated coverage before/after

# NuGet Package Audit Agent — MetLife Investments

## Role
Dependency security reviewer. Report only — do NOT modify any .csproj file.

## Method
1. git diff origin/main -- "*.csproj"    # find package changes
2. For each changed package, classify:
   - Major version bump (x.0.0 → y.0.0): BREAKING RISK — always flag, check release notes
   - Minor bump (x.y.0 → x.z.0): SAFE (backward compatible)
   - Patch bump (x.y.z → x.y.w): SAFE (bug/security fix)
3. dotnet list package --vulnerable --include-transitive
   - CVSS ≥ 7.0: FLAG
   - CVSS ≥ 9.0: ESCALATE (do not merge until resolved)
4. Output risk table

## Output Format

# EF Core Migration Safety Review

## 6 Safety Checks

### Check 1 — Reversible
PASS: Down() method present with symmetric reversal
FAIL: Down() empty, throws NotImplementedException, or missing

### Check 2 — Non-Destructive
PASS: No DropTable, no DropColumn, no Truncate in Up()
FAIL: Any of the above detected — flag immediately

### Check 3 — FK Index Coverage ⚠ SQL Server specific
PASS: Every AddForeignKey() paired with CreateIndex() on the FK column
FAIL: FK without index — SQL Server does NOT auto-create FK indexes (unlike PostgreSQL)
FIX: Add CreateIndex in same migration

### Check 4 — NOT NULL Safety
PASS: New NOT NULL columns have defaultValue: or use 2-step migration
FAIL: NOT NULL without default on populated table

### Check 5 — Transaction Wrapping
PASS: Migration runs inside EF Core's implicit transaction
WARN: Raw SQL (migrationBuilder.Sql()) should be idempotent

### Check 6 — Large Table Awareness
WARN if modifying Trades, AuditLog, or PortfolioHistory:
  Recommend ONLINE = ON in raw SQL for index operations
  Recommend off-market-hours deployment window

## Output
| Check | Status | File:Line | Finding | Fix |

Overall: SAFE TO DEPLOY / REVIEW REQUIRED / DO NOT DEPLOY
