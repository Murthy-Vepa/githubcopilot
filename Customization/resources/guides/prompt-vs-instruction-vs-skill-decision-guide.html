Customization decision guide

Scenario-based guide

Prompt, instruction, or Skill?

Choose the right way to give Copilot context or reusable expertise. Start with activation, repetition, and the amount of workflow detail you need.

6 scenariosDecision-first

The short answer

Choose by activation and reuse

Prompt

Use for a focused request that a person deliberately invokes now.

Instruction

Use for durable rules that should apply automatically in a defined context.

Skill

Use for reusable specialist knowledge, resources, and a repeatable procedure.

Real situations

Scenario-based decisions

Scenario 1: “Use our naming and testing rules every time.”

The rule applies to a known set of files and should not depend on remembering a prompt.

Choose: Instruction. Scope it to the relevant files and keep the rules short, observable, and testable.

Scenario 2: “Create a release summary when I ask.”

The user wants the same headings and evidence each time, but not on every conversation.

Choose: Prompt. Define inputs, output headings, and what to do when evidence is missing.

Scenario 3: “Investigate incidents using our redaction policy and queries.”

The process needs domain guidance, reference files, examples, and several repeatable steps.

Choose: Skill. Put the compact procedure in the Skill and keep supporting material as discoverable resources.

Scenario 4: “We are still learning what works.”

The team has one example and no stable expected behavior.

Choose: Prompt first. Experiment manually, capture the recurring pattern, then promote it only when the benefit is clear.

Scenario 5: “The same recipe needs different inputs by repository.”

The workflow is shared, but each repository supplies its own paths, commands, and validation.

Choose: Skill plus scoped instructions. Keep reusable procedure in the Skill and repository-specific facts in instructions.

Scenario 6: “The guidance is now hundreds of lines long.”

Large always-on instructions are consuming context and causing unrelated responses to drift.

Choose: Refactor into a Skill. Leave only durable rules in instructions and move conditional workflow detail into the Skill.

Before you create it

Decision checklist

  • Activation is clear
  • The behavior can be tested
  • Scope is no broader than needed
  • Repeated detail has a maintained home
  • Secrets are excluded
  • Non-matching tasks remain unaffected
Rule of thumb: Prompt for now, instruction for always here, Skill for reusable expertise.
