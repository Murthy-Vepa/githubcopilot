Scenario-based guide

Agent or custom agent?

Decide whether built-in agent behavior is enough or whether your team needs a named, bounded role with its own instructions, tools, and handoffs.

5 scenariosRole clarity

The short answer

Start with the task, then add boundaries

Use an agent

When a general agent can complete the task with existing context, tools, and review.

Use a custom agent

When a recurring role needs distinct responsibilities, tools, outputs, or permission boundaries.

Real situations

Scenario-based decisions

Scenario 1: “Fix this failing test and show me the diff.”

The task is local, the developer will review the change, and no special permissions are required.

Choose: Agent. Give the task relevant files and a validation command, then inspect the result.

Scenario 2: “Create a plan but do not modify files.”

Planning is a distinct phase with a read-only contract and a required output format.

Choose: Custom Planner agent. Define read-only tools, required evidence, and a clear stop condition.

Scenario 3: “Build, test, and review releases through separate owners.”

Different stages have different risk, tools, and accountability.

Choose: Multiple custom agents. Use explicit handoffs and human approval before consequential stages.

Scenario 4: “The agent needs a specialist database procedure.”

The role is unchanged, but the task needs reusable database expertise and reference material.

Choose: Agent plus Skill. Keep role coordination in the agent and domain procedure in the Skill.

Scenario 5: “We want an agent that can use every available tool.”

The request is motivated by convenience rather than a defined workflow.

Choose: Neither yet. Define the job, narrow tools to least privilege, and add a custom role only when its boundary is testable.

Before you specialize

Decision checklist

  • The role has a recurring purpose
  • Responsibilities are distinct from normal agent work
  • Tools are limited and justified
  • Inputs and outputs are explicit
  • Stop and approval conditions are documented
  • The role can be tested with representative tasks
Rule of thumb: use a general agent for a task, and a custom agent for a role with a durable contract.
