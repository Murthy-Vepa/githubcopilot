MCP server or plugin?

Choose between a protocol-based connection for tools and data, and a product-specific extension when you need a deeper host integration.

5 scenariosTrust-aware

The short answer

Choose by boundary and host dependency

Use an MCP server

When capabilities should be exposed through a portable, explicit tool and resource contract.

Use a plugin

When the host product provides a plugin model and the experience needs host-specific UI or lifecycle integration.

Real situations

Scenario-based decisions

Scenario 1: “Copilot should look up service ownership.”

The data is in an internal catalog and should be available through one read-only operation.

Choose: MCP server. Expose a narrow lookup tool, authenticate it, and document the trust boundary.

Scenario 2: “Add a deployment dashboard inside one IDE.”

The experience needs a panel, host commands, and IDE lifecycle events.

Choose: Plugin. The host-specific UI and lifecycle are central to the feature.

Scenario 3: “Expose approved test data tools to several assistants.”

The same capability should work across compatible AI clients with consistent contracts.

Choose: MCP server. Keep the tool schema, permissions, and failure behavior portable.

Scenario 4: “The integration needs broad host access.”

The proposal asks for filesystem, network, and write access without a defined task boundary.

Choose: neither yet. Narrow the use case and permissions before choosing an integration model.

Scenario 5: “The host has a mature plugin marketplace.”

Distribution, settings, UI, and updates are all managed through that host's extension system.

Choose: Plugin. Use the native distribution and lifecycle model, while keeping backend capabilities narrowly scoped.

Trust checklist

Before connecting anything

  • Capability and host boundary are explicit
  • Read and write operations are separated
  • Credentials are externalized
  • Tool inputs and side effects are documented
  • Failure and revocation paths are tested
  • Distribution and updates have an owner
Rule of thumb: MCP is the portable capability boundary; a plugin is the host-specific product integration.
