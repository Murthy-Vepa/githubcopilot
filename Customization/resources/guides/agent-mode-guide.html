Unit 02 → What is Agent Mode?
The core concept

From suggestion to collaborator

Traditional coding assistance usually responds to the immediate context. Agent Mode takes a project-wide view and dynamically works through a task until it reaches a useful, testable result.

Inline Suggestions

Real-time completions as you type. Useful for focused implementation and boilerplate.

Copilot Chat

Ask questions and receive project-aware explanations, recommendations, and code guidance.

Copilot Edits

Coordinate broader changes across selected files around a specific goal.

Agent Mode

Analyze, plan, edit, run commands, test, inspect failures, and iterate across the workspace.

🧭
The key shift: describe the outcome rather than prescribing every implementation step. Agent Mode determines relevant files and dependencies, proposes changes, executes approved actions, and refines its work.
Outcome-oriented prompt
Build a responsive activity dashboard for the existing application. Use the current design system and data models. Include loading, empty, and error states. First inspect the project structure and tell me which files you plan to change. After implementation, run the relevant tests and summarize any remaining risks.

Unit 03 → Explore the power
Autonomous development assistance

How Agent Mode works through complexity

Agent Mode is valuable when a request spans multiple files, commands, dependencies, tests, or design decisions. Its autonomy is useful because the work is orchestrated, but its actions remain visible and reviewable.

01
Analyze the project
Inspect files, dependencies, scripts, conventions, and prior context to identify the relevant change surface.
02
Plan the multi-step task
Break a request such as a new API or database integration into dependencies, source files, configuration, and tests.
03
Use tools and execute
Create or edit files, install dependencies when appropriate, run builds and tests, and use the existing project workflow.
04
Detect and self-heal
When a test or command fails, identify the cause, apply a correction, and rerun validation rather than stopping at the first draft.
05
Return control to the developer
Review the summary and diff, request changes, revert unwanted work, and decide whether the result is ready to keep.
⚠️
Practical limit: missing documentation, specialized domain rules, or ambiguous business logic can produce incomplete or inaccurate changes. Give Agent Mode context, then verify the result yourself.

Apply it → A repeatable agent workflow
Prompt, inspect, verify

The draft → review → accept loop

Use Agent Mode to carry the mechanical work, while you define the acceptance bar. A strong task includes its scope, constraints, context, and verification command.

1. State the outcome

“Add an endpoint,” “refactor the parser,” or “migrate this feature” is a useful start. Name the user-visible result.

2. Add constraints

Preserve public APIs, follow existing patterns, avoid specific files, maintain compatibility, or limit the scope.

3. Ask for a plan

For cross-cutting work, ask Agent Mode to inspect the repository and list intended changes before execution.

4. Require verification

Include the build, test, lint, or smoke command and ask the agent to fix failures before reporting completion.

Agent task template
Task: [describe the outcome] Context: [files, feature, architecture, or business rule] Constraints: [what must remain unchanged] Acceptance criteria: - [observable behavior] - [edge case] - [test or quality requirement] Verification: Run [command]. Fix failures and report the result. Before editing: summarize the plan and assumptions.
✅
Accept only after review: read the changed files, inspect the diff, check security and error handling, run the verification command, and confirm the implementation matches the request.
Apply it → Documentation and oversight
Make context durable

Documentation is part of the prompt

README files and project documentation are not only for people. They give Agent Mode the intended behavior, setup instructions, architecture clues, and conventions it needs to make better autonomous decisions.

README.md

Explain what the project does, how to run it, important workflows, and where the major pieces live.

Architecture notes

Record boundaries, dependencies, data flow, integration contracts, and decisions that are not obvious from the code.

Development scripts

Make build, test, lint, and validation commands discoverable and reliable in local or Codespaces environments.

Guardrails

State security rules, sensitive areas, generated-file boundaries, review expectations, and commands that should not be changed.

Useful project guidance
# Development guidance - Use the existing project structure and naming conventions. - Do not change workflow files unless the task explicitly requires it. - Keep secrets in environment variables and never commit credentials. - Add tests for changed behavior and run the relevant validation command. - Explain any assumptions about undocumented business rules before editing.
🔍
Control remains human: Agent Mode can propose extensive changes, but you can review, revise, undo, or narrow them at every stage.
Unit 04 → GitHub Skills exercise
Hands-on practice

Build OctoFit Tracker

The exercise places you in a GitHub Codespace and asks you to build a social fitness application for students with GitHub Copilot Agent Mode.

Application features

  • User profiles for students and gym teachers.
  • Activity tracking and progress.
  • Team creation and management.
  • Leaderboards for student performance.
  • Personalized workout suggestions.

Workshop sequence

  1. Set up a Codespace.
  2. Install and configure Copilot.
  3. Generate and refine app components.
  4. Implement profiles, tracking, teams, and leaderboards.
  5. Test and optimize the generated code.
🛑
Exercise integrity: follow the repository README and do not modify workflow files. Changing validation workflows can break exercise grading and feedback.

Unit 05 → Module assessment
Check your understanding

Can you explain the agent?

Before moving on, use this checklist to test the concepts covered by the official assessment.

  • Explain how Agent Mode differs from inline suggestions and single-file assistance.
  • Describe how Agent Mode analyzes a project and identifies dependencies.
  • Explain how it autonomously performs multi-step changes and runs tools.
  • Describe how testing can reveal issues that Agent Mode then corrects.
  • Explain how README and project documentation influence its behavior.
  • Identify when domain-specific knowledge requires more human guidance.
  • Describe how to review, modify, or undo proposed changes.
  • Recognize that autonomy does not remove developer accountability.
🧠
Assessment lens: the correct answer is usually the one that combines autonomous project-wide action with iterative verification and continued developer oversight.

Unit 06 → Summary and references
Carry it into your workflow

Autonomous does not mean unaccountable

GitHub Copilot Agent Mode combines project awareness, tool use, multi-step execution, and iterative correction. Used well, it lets developers spend more time on product decisions and less time on repetitive implementation.

Build

Prompt Agent Mode to create an application or feature from a clear outcome.

Guide

Use documentation, repository conventions, and explicit constraints to improve the quality of autonomous work.

Improve

Let Agent Mode find errors, refactor code, develop features, and re-run validation across the project.

Own

Review every meaningful change and remain accountable for security, correctness, maintainability, and fit.
