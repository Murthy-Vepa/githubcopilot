Prompts, Instructions
& Skills

Give Copilot a permanent memory of your codebase, coding standards, and team workflows using instructions files, prompt templates and skill packages.

📋 copilot-instructions.md
📋Anatomy of the global instructions file
Location
.github/copilot-instructions.md
Loaded automatically for every chat in this repo. No explicit trigger needed.
Purpose
Repo-level persistent context
Coding conventions, tech stack, architecture principles, team standards.
Limit
~4,000 tokens recommended
Keep it focused. Long files dilute signal. Use .instructions.md for per-path rules.
📝Example: MetLife .NET 10 instructions
# .github/copilot-instructions.md
## Stack
- .NET 10, Razor Pages, EF Core, SQL Server
- xUnit for tests, FluentAssertions

## Conventions
- Always use nullable reference types (`#nullable enable`)
- Repository pattern: `IRepository<T>` interface
- No raw SQL — use EF Core LINQ only
- Structured logging via `ILogger<T>`, never Console.Write

## Security
- Never log PII or connection strings
- Validate all user input at the controller boundary
🎯 .instructions.md — Scoped Rules
🎯applyTo patterns

Place .instructions.md files anywhere in the repo. The applyTo frontmatter controls which files trigger them — perfect for language-specific rules.

applyToGlob pattern. '**' = always. '**/*.cs' = C# files only. 'src/api/**' = specific folder.
PriorityCloser to the file wins. Folder-level .instructions.md overrides repo-level for matching files.
📄Examples for different file types
--- # src/Data/.instructions.md
applyTo: '**/*.cs'
---
Always use parameterised queries.
Never call SaveChangesAsync inside a loop.

--- # wwwroot/.instructions.md
applyTo: '**/*.{js,ts}'
---
Use strict mode. No var, only const/let.
Prefer fetch() over XMLHttpRequest.
✍️ .prompt.md — Reusable Templates
✍️Anatomy of a prompt template
Location
.github/prompts/*.prompt.md
Discoverable via VS Code command palette: "Chat: Run Prompt".
Variables
${{variableName}}
Inject dynamic values at run-time via prompt input fields.
mode
ask | edit | agent
Controls whether the prompt asks, edits current file, or runs as an agent workflow.
📄Example: scaffold a new endpoint
---
description: Scaffold a new Razor Page with service + repo
mode: agent
variables:
  - name: EntityName
    description: PascalCase entity (e.g. Invoice)
---
Create a full CRUD Razor Page for
`${{EntityName}}` following the existing
TodoItem pattern in src/TodoApp/Pages/.
Include xUnit tests in TodoApp.Tests/.
🎯 SKILL.md — Domain Knowledge Packages
🎯What is a SKILL.md?

A SKILL.md is a self-contained domain knowledge capsule. It defines when to load it (trigger words), what it knows (step-by-step procedures), and what tools it uses.

Triggers
description + when/not-when rules
Semantic similarity matching — no exact keyword required.
Content
Step-by-step procedures, patterns, examples
Loaded on demand — keeps context window lean.
Location
.github/skills/my-skill/SKILL.md
Each skill lives in its own sub-folder.
📄Example: a .NET deployment skill
---
name: dotnet-azure-deploy
description: Deploy .NET 10 apps to Azure App Service
  using Bicep + azd. WHEN: "deploy to Azure",
  "publish to App Service", "azd up".
  DO NOT USE FOR: Docker-only deployments.
---
## Steps
1. Run `azd init` to scaffold infra/
2. Edit `infra/main.bicep` — set SKU to B2
3. `azd provision` → `azd deploy`
4. Verify health endpoint: `/health`
📦 Copilot SDK & Extensions
📦@github/copilot-sdk quick start
# Install
npm install @github/copilot-sdk

// Create a session and send a message
import { CopilotClient } from '@github/copilot-sdk'

const client = new CopilotClient({ token })
const session = await client.createSession({
  model: 'gpt-4o',
  instructions: 'You are a .NET expert.'
})
const reply = await session.sendAndWait(
  'Review this PR for security issues'
)
