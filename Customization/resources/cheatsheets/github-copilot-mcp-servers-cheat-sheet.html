External toolsExplicit accessReviewable boundaries

Core concepts

Server

Provides one or more tools, resources, or prompts through MCP.

Tool

Defines an operation with a name, input schema, handler, and result.

Transport

Controls how the client reaches the server, such as local process or remote endpoint.

Identity

Determines what the server can access and how credentials are supplied.

Before enabling a server

CheckQuestion
PurposeWhat user workflow does this server enable?
ToolsWhich tools exist, and which can write, delete, send, or publish?
InputsAre schemas validated and untrusted input handled safely?
AccessWhat files, network destinations, identities, and secrets are available?
OutputCan results contain secrets, prompt injection, or sensitive business data?
OwnershipWho maintains, scans, updates, and disables the server?

Tool design and safe usage

Tool design

NamePrecise and descriptive.
ScopeOne clear responsibility.
InputsEvery argument is validated.
EffectsSide effects are obvious.

Usage pattern

discover tool -> inspect schema
-> validate input -> approve if needed
-> execute -> verify result
Remember: an MCP server expands capability and risk together. Expose the smallest useful tool surface and review the implementation before connecting it.
