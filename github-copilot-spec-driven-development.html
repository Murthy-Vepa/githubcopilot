Spec-Driven Development

Turn intent into shared understanding, executable plans, and evidence-backed delivery.

IntentSpecificationPlanProof
01 / Introduction

SDD makes the thing being built understandable before it becomes expensive to change.

A specification gives people and AI a shared reference for behavior, constraints, scenarios, and success. It turns a conversation into an artifact the team can inspect and improve.

Align

Make the problem, users, scope, and desired outcomes visible to the people doing the work.

De-risk

Expose assumptions, edge cases, dependencies, and non-functional needs early.

Accelerate

Give developers and AI a stable target so implementation starts with less ambiguity.

SDD is a way of working:the specification is a living collaboration surface, not paperwork produced after the important decisions are already made.
02 / Concepts

SDD connects four artifacts into one delivery loop.

01

Spec

What should the system do, for whom, and under what constraints?

02

Plan

How will the team change the system, in what order, and with what dependencies?

03

Tasks

What bounded work can be implemented, reviewed, and tested independently?

04

Evidence

What checks demonstrate that the delivered behavior matches the intent?

Traceability is the connective tissue:every implementation decision should be explainable against a requirement, scenario, constraint, or quality gate.
03 / Two working modes

Vibe Coding explores quickly; SDD makes the path repeatable.

Vibe Coding

  • Conversational and exploratory.
  • Useful for sketches, learning, and rapid discovery.
  • Risk: assumptions can remain implicit.

Spec-Driven Development

  • Explicit and collaborative.
  • Useful when work has consequence, dependencies, or multiple contributors.
  • Strength: decisions and acceptance criteria remain visible.
They are complementary:use exploration to discover the shape of a problem, then use a specification when the team needs a shared contract for delivery.

04 / AI-driven SDD

AI can help move a team through the SDD loop without owning the decisions.

DiscoverAsk AI to identify unknowns, users, scenarios, risks, and questions worth resolving.
SpecifyDraft requirements and acceptance criteria, then refine them with the people who own the outcome.
PlanTranslate the agreed behavior into architecture notes, dependencies, tasks, and quality gates.
Implement and proveGenerate bounded changes, run checks, and trace evidence back to the specification.
AI is a force multiplier for clarity:it can surface gaps and produce drafts, but the team remains accountable for priorities, tradeoffs, and acceptance.

06 / GitHub Spec Kit

GitHub Spec Kit makes specification a first-class development artifact.

Core flow

  • Establish project principles and constraints.
  • Describe the feature and user scenarios.
  • Clarify ambiguities before planning.
  • Generate a plan and actionable tasks.

Why it helps

  • Creates a shared vocabulary for intent.
  • Supports traceability from requirements to implementation.
  • Gives AI a stable, structured context.
  • Encourages quality gates before delivery.
Spec Kit is a workflow, not a magic prompt:its value comes from the discipline of refining artifacts and keeping the team aligned as the implementation evolves.

07 / Spec Kit flow

Move from a vague idea to an executable change.

constitution # principles and non-negotiables
specify # requirements, scenarios, acceptance
clarify # resolve ambiguity before planning
plan # architecture, dependencies, implementation strategy
tasks # bounded work with traceability
implement # execute, verify, and update evidence
The command names are less important than the behavior:each stage should reduce uncertainty and leave an artifact that makes the next stage easier to review.

08 / Agent Squad

Agent Squad turns a complex delivery workflow into coordinated responsibilities.

Specialists

Assign focused roles such as analyst, architect, developer, tester, or reviewer.

Artifacts

Make handoffs explicit through specifications, plans, task lists, findings, and evidence.

Gates

Require quality checks at the boundaries where an incorrect assumption becomes expensive.

Squads need orchestration:define ownership, dependencies, communication format, escalation paths, and when a human must approve the next step.

09 / Coordinated delivery

Agent collaboration works when each handoff preserves intent.

01

Frame

Establish the problem, scope, principles, and success criteria.

02

Design

Resolve architecture, dependencies, risks, and implementation choices.

03

Build

Implement bounded tasks against the agreed specification and plan.

04

Verify

Review behavior, run checks, and report evidence back to the shared record.

Coordination is not parallelism for its own sake:use multiple agents when distinct responsibilities reduce risk or increase useful throughput.
10 / Quality gates

Gates keep the SDD artifacts honest.

Before implementation

  • Are the scenarios and acceptance criteria testable?
  • Are non-goals, dependencies, and risks explicit?
  • Does the plan cover the specification?

Before completion

  • Does the implementation trace to the agreed behavior?
  • Do tests and checks provide meaningful evidence?
  • Are deviations documented and accepted?
A gate is a decision point:it should produce a clear pass, fail, or request for clarification, with an owner for the next action.
11 / Adoption pattern

Adopt SDD in a way that earns trust through useful practice.

Start smallChoose one feature workflow where unclear requirements currently create rework.
Make artifacts usefulKeep specifications concise, discoverable, and connected to the work people actually do.
Measure the loopLook for fewer late clarifications, clearer reviews, faster onboarding, and stronger evidence.
Scale the patternCapture principles, templates, roles, and quality gates only after the workflow proves valuable.
Adoption is a product problem:the process has to make developers more effective in their real environment, not merely add a new document type.
12 / Practice path

Practice SDD as a sequence of increasingly explicit decisions.

Describe

Write the user outcome and a small set of concrete scenarios.

Challenge

Ask AI and teammates to find ambiguity, edge cases, and missing constraints.

Prove

Implement a bounded task and connect tests and review evidence back to the spec.

The habit compounds:each clear specification becomes reusable context for planning, implementation, onboarding, and future change.

13 / Responsible SDD

Keep the specification human-owned and the evidence inspectable.

Ownership

The people accountable for the outcome approve the requirements and tradeoffs.

Transparency

Show assumptions, generated contributions, deviations, and unresolved uncertainty.

Security

Protect sensitive context and govern the tools and agents that can act on the project.

Automation can accelerate a bad decision:SDD creates more value when the team uses its artifacts to question decisions, not simply formalize them.
14 / Next steps

Choose one upcoming feature and write the first useful specification.

Name the user outcome, write the scenarios, ask what is unclear, and agree on what evidence will count as done. Then use AI to help the team move from a shared understanding to an executable plan.
